# Original archive retirement and ARM64 idle attribution

## M4 archive retirement

The pinned Original backend again exceeded the five-second retirement limit after a strict archive decode. FFmpeg exited zero after decoding audio and 199 video frames, and the disposable project passed exact cleanup. The live archive connection was still present with the same delivered-byte count at the final follow-up sample, 74.94 seconds after observation began. The current Rust package was verified by metadata for fixture admission. The fixture ran Original only. [Scope and redacted evidence](../scripts/rust-integration/m4-2d3ffe53-original-archive-provider-join.json)

The observer tied Origin connection 2 to one owned Original proxy process and one WSGI `206` archive response. It recorded the provider and WSGI response close callbacks for that request. The decoder-side HTTP transport could not be joined to that response, so the cause of the retirement failure remains unresolved. The separate current functional DVR package check passed.

## M9 idle process accounting

The 210-second Original-only idle run recorded 57,761,792 bytes of additional cgroup anonymous charge between its early and late sample medians. Readable Celery processes gained 57,423,872 bytes of PSS over that same idle contrast. Six root-owned Original application processes and one Origin process did not expose memory rollups to the observer. Complete per-process totals remain unavailable. The figures narrow the observed idle growth to a readable workload component, with the earlier playback-and-guide growth and the M9 release performance gate still open.
