# Observed normal channel-task failure boundary

Original Dispatcharr, Django, Celery, PostgreSQL and dependency authors retain all
credit and licenses. This additive four-path proposal applies AFTER the frozen
nine-path success overlay; it does not modify that proposal or Root's candidate.
Rustfmt0 only; no Cargo or Native runtime validation has run for this overlay.

One genuinely new, dispatcher-leased Source-only ordinary fixture measured nine
actual tasks using the unmodified pinned Original application and prefork worker:
four normal SUCCESS returns, four controlled owned PostgreSQL errors, and the
missing-logo-arguments ValueError. Source API calls/replays0; no media, network
contacts or performance measurement. Actual3 controller/guest/dispatcher0;
all68 read-only semantic checks pass. The first two attempts failed before task
execution (missing retained Docker config, then required Django signing key).
Their raw failures remain failed; exact absence and default-state proofs remain
separate. Actual3 uses an ephemeral in-memory key, never recorded or published.

The actual failure mapping is P0001→ProgrammingError,22001→DataError,
23505/23514→IntegrityError in django.db.utils; missing arguments→builtins
ValueError. Actual exception messages include PostgreSQL CONTEXT. The Source
worker sends the task-specific failed progress (task ID,progress0,total,message,
error), then stores Celery FAILURE. Those observations, exact backend bytes,
raw/decoded Channels bytes, SQL changes and Python traceback are retained in the
new dataset. SQL snapshot JSON strings are parsed solely for derived row diffs.

The proposed Store outcome distinguishes an original settled SQL exception from
Ready/close/acquire uncertainty and unsupported profiles. Only actual ERROR
severity, no cursor-position diagnostics and the measured SQLSTATEs classify as
task failures. Primary/detail/hint/context fields and assembled output are
bounded. The handler emits failed progress, writes actual FAILURE, and returns
TaskFailed; failed/ambiguous backend publication retains admission and faults.
No guessed SUCCESS or silent retry follows. Missing-logo arguments execute the
observed ValueError path without SQL/body effects.

The traceback is an explicit Native diagnostic describing the actual settled
boundary. It contains no invented Python frames and is deliberately different
from Source's retained traceback bytes. This difference is a compatibility gate,
not a claim of byte-identical tracebacks. Native grouped API/worker/SQL/error
acceptance, unmeasured SQLSTATEs/cursor positions/oversized diagnostics,
malformed input coercions, all previously declared bounded/concurrency profiles
and full M6 remain open. Source backend failure evidence alone does not accept
the new Native code.

Input provenance scope: dispatcher bound the driver/guest/bootstrap/Original
archive before application start. Schema/pg-init/state.py were inherited copied
retained helpers but were not independently pre-bound in the dispatcher; the
post-run executed-helper inventory explicitly records that narrower assurance.
