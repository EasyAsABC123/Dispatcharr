# Signed APT closure for the ARM64 FFmpeg source build

Ubuntu APT 3.2.0 resolved both stages of the upstream FFmpeg recipe against the historical snapshot at `20261102T221537Z`. The verified amd64 sibling supplies the locally executed APT tools and matches the APT version recorded in the Original ARM64 base. The solver reads the exact ARM64 package status and Canonical-signed indexes from scratch, inside an isolated network namespace. An independent replay reproduced all six simulated commands and package rows. [Original source and Ubuntu input provenance](rust-m10-arm64-ffmpeg-source-inputs.md) · [Canonical snapshot service](https://snapshot.ubuntu.com/)

The two builder commands select 279 and 33 package rows. The two runtime commands select 67 and two. The Original runtime recipe and the explicitly pinned replay agree on all 25 exact recorded runtime versions, with zero package removals and no dependency conflict. The first command's planned package metadata supplies the simulated status for each second command. The simulation leaves package installation and post-install scripts to the eventual native build. [Recursive package lock receipt](../scripts/rust-integration/m10-native-arm64-ffmpeg-apt-closure.json)

All 312 selected package archives match Canonical's signed hashes and sizes, and their Package, Version and Architecture fields were read back from the archives. The complete private lock also includes nine source archives and 15 signed index or by-hash paths. The source recipe accepted those actual inputs and rendered the offline native build context. A new native build still needs to install and compile the lock, compare executable hashes and run the media check. Historical compiler byte identity and distribution qualification remain open. [Exact upstream recipe](https://github.com/Dispatcharr/FFmpeg/releases/tag/v9.0.2-nvenc130-fce79836385e)
