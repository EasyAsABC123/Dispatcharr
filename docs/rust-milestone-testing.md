# Milestone-wide Rust validation

The November14 direction is to validate complete milestones together. A passing
component is useful evidence; the milestone batch is the unit of delivery.
Original Dispatcharr and dependency authors retain full credit and licensing.
React remains unchanged.

The reusable [migration-milestone-testing skill](https://github.com/EasyAsABC123/agent-skills/tree/main/skills/migration-milestone-testing)
records this workflow and the lessons from the existing runs. It replaces the
internal practice of separate admission and publication cycles for every helper.
Existing evidence, failed attempts and Source references remain intact.

| Batch | Owner | Required integrated coverage |
| --- | --- | --- |
| M0/M1 prerequisites | Primary agent | Required executable Source contracts, reproducible baseline, existing core evidence and literal acceptance accounting. |
| M2/M3/M5 | Streaming/API agent | Actual Main authentication, playback/fanout, formats/profiles, settings consumers, React workflows, failures and cleanup on one candidate. |
| M6 | Jobs/ingestion agent | Producer/API202 to default FIFO intake, ingestion/EPG, configured Series descendants, scheduling, recording and recovery. |
| M4/M7/M8 | Protocol/operations agent | VOD/timeshift, output protocols, realtime, plugins, backup/admin/config and operational workflows, with unresolved capabilities explicit. |
| M9 | Primary agent with all owners | Final combined Compose/package/SDK, whole-workflow regression, restart/soak/rollback and representative paired performance after prerequisites pass. |

Each owner is preparing one executable matrix from existing runners. Matrix
entries identify the Source authority, actual application entry point, fixture,
dependencies, expected effects and status. Missing implementations are blockers;
501 responses, ignored tests and unexecuted cells do not become passes. A batch
continues independent cells after failure when isolation remains valid.

Build the shared candidate once. Reuse Compose bootstrap within a cohort using
explicit state boundaries; use separate owned namespaces where isolation needs
it. One batch definition covers its ready cases and resource limits. Run
independent functional nodes in parallel within the existing three-fixture
budget. Serialize actual state/subnet dependencies and run resource measurements
alone. Use focused tests to diagnose failure, then retest affected dependencies
and the complete milestone before acceptance.

Keep one shared Cargo target in place. Preserve logs, source identities,
necessary binaries and compact lossless evidence rather than another target or
full application bootstrap per assertion. Record actual exits and attempted vs
completed operations. Reuse qualified Source observations; capture missing
Source behavior as grouped prerequisites, without replaying references merely to
improve a controller status.

The latest combined candidate has929 inputs and passes all four workspace
checks, with888 default tests passed and751 external-fixture tests ignored across172
result blocks. Its [packaged Main cohort](rust-m6-packaged-main-batch3.md) passes170
assertions, including the natural TVG task, descendants and failure continuation.
Actual settings PATCH405 and fresh-install Series no-rules handling are current
integration gaps; default scheduler/worker coverage remains incomplete. The
four plugin ownership cases, corrected51-call settings cohort, bounded61-second
normal recording and held-result case have separate qualified source epochs.
Those are preparation for the broader batches, not full milestone acceptance.
The historical Source TS cache capture establishes inherited Base hits only;
cold TS and actual expiry remain unmeasured. Testing only a later descendant
cannot establish default FIFO completion.

Paired performance follows the functional batch and uses equivalent useful work,
fixed budgets and a declared full resource boundary. Include compatibility
workers and media processes. Correctly distinguish working memory, RSS and PSS.
Existing image57 results retain their original source/workload scope; they do
not establish gains for the current candidate or the full worker graph. The
[new resource preflight](rust-milestone-batch2-resource-preflight.md) failed before
any Native measurement and supplies no accepted comparison. All formal
milestones retain their current open status until their required criteria pass.
