# Milestone-wide Rust validation

The November14 direction is to validate complete milestones together. A passing
component is useful evidence; the milestone batch is the unit of delivery.
Original Dispatcharr and dependency authors retain full credit and licensing.
React remains unchanged.

The reusable [migration-milestone-testing skill](https://github.com/EasyAsABC123/agent-skills/tree/main/skills/migration-milestone-testing)
records this workflow and the lessons from the existing runs. It replaces the
internal practice of separate admission and publication cycles for every helper.
Existing evidence, failed attempts and Source references remain intact.

| Batch | Owner | Required integrated coverage |
| --- | --- | --- |
| M0/M1 prerequisites | Primary agent | Required executable Source contracts, reproducible baseline, existing core evidence and literal acceptance accounting. |
| M2/M3/M5 | Streaming/API agent | Actual Main authentication, playback/fanout, formats/profiles, settings consumers, React workflows, failures and cleanup on one candidate. |
| M6 | Jobs/ingestion agent | Producer/API202 to default FIFO intake, ingestion/EPG, configured Series descendants, scheduling, recording and recovery. |
| M4/M7/M8 | Protocol/operations agent | VOD/timeshift, output protocols, realtime, plugins, backup/admin/config and operational workflows, with unresolved capabilities explicit. |
| M9 | Primary agent with all owners | Final combined Compose/package/SDK, whole-workflow regression, restart/soak/rollback and representative paired performance after prerequisites pass. |

Each owner is preparing one executable matrix from existing runners. Matrix
entries identify the Source authority, actual application entry point, fixture,
dependencies, expected effects and status. Missing implementations are blockers;
501 responses, ignored tests and unexecuted cells do not become passes. A batch
continues independent cells after failure when isolation remains valid.

Build the shared candidate once. Reuse Compose bootstrap within a cohort using
explicit state boundaries; use separate owned namespaces where isolation needs
it. One batch definition covers its ready cases and resource limits. Run
independent functional nodes in parallel within the existing three-fixture
budget. Serialize actual state/subnet dependencies and run resource measurements
alone. Use focused tests to diagnose failure, then retest affected dependencies
and the complete milestone before acceptance.

Keep one shared Cargo target in place. Preserve logs, source identities,
necessary binaries and compact lossless evidence rather than another target or
full application bootstrap per assertion. Record actual exits and attempted vs
completed operations. Reuse qualified Source observations; capture missing
Source behavior as grouped prerequisites, without replaying references merely to
improve a controller status.

## Build and fixture lessons from Candidates43–45

A successful Docker command is insufficient when compilation caches are shared.
The source archive normalizes timestamps to zero; Cargo's timestamp checks then
reused Candidate43 executables despite Candidate44's seven changed Rust files.
The [negative comparison](../scripts/rust-integration/milestone-batch44/package/UNTRUSTED.json)
keeps CLI success separate from code provenance. Every uncached Cargo build must
refresh all local compile-input timestamps before compilation. Keep registry
caches, record actual local-crate compilation, and verify the changed Main ELF.
Runtime-only layer hits can still reuse an unchanged compiled layer. Never count
a stale executable's short build as a speed improvement.

Compose the real recording router during cheap development checks. Candidate43's
modules compiled, but its separate Comskip route conflicted with the existing
catchall and panicked at Main startup. The regression now composes the same
recording, playback and Comskip services used by Main, with closed lazy services
to distinguish dispatch without SQL. The complete application batch is still
required after this development check.

Fixture ownership must match the actual rootless mapping. Preserve captured
input bytes; stage a current-user-owned copy instead of archiving an out-of-range
host subuid. Change ownership only through the existing owned fixture setup;
production Main remains UID65532 with capabilities dropped. The
[staging controls](../scripts/rust-integration/milestone-batch44/copy-staging/qualification.json)
also retain observer failures from an unnecessary chmod and a mode0700 parent.
Use the real Fixture's directory mode and operations, not additional permission
steps. Disable Python bytecode before importing frozen helpers so validation does
not create unreadable mode0700 cache directories in the bound source closure.

## Keep fixture failures distinct from application failures

[SDK63 physical validation](../scripts/rust-integration/milestone-batch46/physical/qualification.json)
needed the existing disposable-fixture marker and an actually published Redis
port. An internal-only Compose network retained requested PortBindings but
published no host port; the next attempt reached only the tests' fixture guard.
Record both failures as executed attempts without transport coverage. Check the
actual resolved port and required guard environment before invoking the existing
compiled physical-test binary. The final three-test batch supplies transport
coverage; an ordinary workspace pass leaves those tests ignored.

Current-Main provider-info characterization also shows why seed setup must
preserve the integration bootstrap. Its existing accounts have live profile,
stream and schedule foreign keys. Allocate separate owned oracle accounts and
translate Source IDs consistently in seed, response, related rows and sequence
baselines; verify bootstrap rows before and after. Preserve failed setup receipts.
A subsequent HTTP200 response can still be stale fallback: examine actual TLS/
HTTP provider attempts and complete SQL observations before interpreting a missing
sequence increment as a database bug. Do not weaken expected provider effects to
accept an unsuccessful refresh.

A clean Git archive export must also preserve traversable helper directory modes.
Python's tarfile `data` filter can leave extracted directory modes to the current
umask; under077 the UID65532 probe cannot traverse0700 helper directories even
when every file checksum and mode is correct. Normalize only owned export helper
directories to0755, verify unchanged file bytes, and use a fresh prepared attempt.
Do not relax the production UID, capabilities or source-file integrity checks.

Positive Comskip characterization also exposed two compound-workflow traps.
Natural booking publishes artwork before the recording root and its Comskip
child; retain that complete three-task graph instead of assuming two tasks.
When MARK and CUT share a fixture, snapshot the existing MARK EDL paths and
hashes before CUT, exclude only those pre-existing files from the new-output
watcher, and verify their bytes remain unchanged afterward. Otherwise an
observer can reject a successful second operation after a 520-second recording.

The manual CUT content reference contains a 3.9 MiB framehash transcript, larger
than the fixture's 1 MiB command-output cap. Keep that cap: write the complete
decoder output to an owned file under an explicit 8 MiB child file-size limit,
wait for the actual decoder, return a compact receipt, and compare the full
file. Syntax and synthetic delegation controls precede the real cohort; they
do not establish media equivalence or application performance. Natural timed
captures with successful A/V decode still need their own content proof.

Use the completed journal's actual terminal barrier to bound backend completion,
not the last selected queue command. A fast Comskip repeat completes after
Native dequeue and Source early acknowledgement; later unrelated Source polling
had accidentally made the old upper bound pass. Validate the complete journal
hash, unique final ECHO, persisted row count and closed/fsynced observer before
using that timestamp. Preserve the failed controller and add no clock tolerance.

When reducing a frozen helper closure, inspect imports inside generated guest
Python strings as well as ordinary host imports. Catalogue receiver setup uses
`matching_guest` through `fixture.sql`; that dependency is invisible to a host-only
module-import audit. Preserve the actual omitted-module failure and add the exact
frozen guest helper with its recursive imports and mount path. Then execute the
complete affected public cohort; static byte equality with a subset is insufficient.

## Compare complete state and control observer cost

Advanced-Series characterization exposed four ID-allocation differences that
entity counts alone missed. PostgreSQL `INSERT ... ON CONFLICT DO NOTHING` can
consume a sequence value even when no row is created. Preserve Source's actual
get-or-create versus bulk-insert behavior, including deliberate conflict burns;
compare all relevant support rows and sequences. Never normalize IDs or sequence
state away to make an otherwise similar import pass.

Shared integration bootstrap is also part of a case's prerequisites. Provider-info
used the configured TiviMate default while its standalone Source reference used
Dispatcharr's fallback. Restore the Source-equivalent setting in that owned
context, verify effective Source getters and actual Native headers, and restore
prior settings before another context. Keep account foreign keys and agent rows
unchanged. Canonicalize complete model rows with a lossless datetime encoder
before comparing them with JSON snapshots. Cache snapshots need atomic value and
absolute-expiry capture; restore only after actual Main/role retirement, retaining
natural expiry and all failed teardown outcomes.

The Candidate47 viewing study retains its CPU-budget miss despite every phase's
valid output. Infrastructure cgroup CPU includes short-lived sampler children;
two process-endpoint inventories cannot attribute that transient work. Include
observer costs exactly as declared and preserve the failure. A persistent observer
is a new instrumentation protocol, requiring fresh Source/Native qualification
and all fresh paired phases. It is not a Rust application optimization or grounds
for subtracting historical cost. Match inherited `REDISCLI_AUTH`, query order,
Lua, cadence and database; killing Docker's CLI alone cannot prove an exec guest
retired. Verify the actual guest/host PID generation and cgroup and bound all pipes,
sockets, deadlines and fallback cleanup.

Validate script readability using the actual child UID at its direct mount. A
root-owned helper wrapper or copied support file can be readable while the proxy's
separately mounted original remains0700/0600. Mode-only repairs must preserve
payload hashes and failed startup receipts; verify the corrected UID before
another complete run.

Generated API URLs can contain an independently assigned fixture listener. Record
the actual port receipt, Main bind address and network namespace before comparing
responses. Validate each complete URL against that run's owned origin and its
SQL-bound logo ID/provider URL. Map only the declared response field's origin;
keep path, query/version hash, scheme and credentials/fragment constraints exact.
Preserve the failed controller result even when an offline comparison proves
fixture entropy. Then run the complete affected cohort with the corrected
observer, without rebuilding unchanged application code or replaying known Source
characterizations.

Typed entropy must also remain stable within a run. Mapping independently
generated fixture credentials to tokens cannot erase a later credential mutation:
compare each subsequent raw value with its initial setup value before mapping it.
Check every reachable launcher path when reusing a runner; updating copied tools
does not help if the launcher still selects its predecessor directory. Keep
original process IDs and generations in durable, credential-free cleanup records.

Do not infer database insertion order from a JSON array's order. Candidate50's
relation `INSERT ... SELECT ... WHERE NOT EXISTS` passed compilation and the
read-only SQL peer, but allocated exposed relation primary keys in a different
order from Source. Its nine local semantic checks passed; strict full-row Source
comparison caught the different stream-to-primary-key mapping. Preserve that
failed run and fix production SQL with `WITH ORDINALITY` and an explicit final
`ORDER BY`. Verify syntax/types on PostgreSQL, rebuild the changed executable,
and rerun the complete affected application cohort. Do not normalize relation
primary keys or replay unchanged Source evidence to obtain acceptance.

Parsing Python syntax does not prove a fixture's preparation function can run.
The grouped catalogue Source run completed twelve roots before its scale context
referenced an undefined forwarding helper. Import the actual prepared module,
check runtime-referenced globals and imported attributes, and exercise its real
preparation delegate with an owned host control before starting applications.
Preserve the original controller failure and completed captures. Run only the
five missing scale roots, and report the two actual controller outcomes instead
of inventing one successful seventeen-root controller.

SQL Parse/Describe checks cannot establish update-selection semantics. Source can
queue an object because its in-memory name changed, then omit that name from
`bulk_update`; its first queued metadata CASE arm still wins. Exercise the exact
production UPDATE with both input orders against typed temporary shadow tables.
Use explicit seed identifiers without advancing sequences, verify complete rows
and affected-row counts, roll back, and prove public rows/sequences unchanged.
Keep these actual DML controls separate from the read-only schema receipt:
rolled-back DML is still executed DML. Reuse the same owned physical executor.

Runner retargeting and chained correction gates:

- Change count fields explicitly; never replace their digits throughout a file. A `66` to `68` count edit also changed the pinned Source archive digest, so checksum preflight stopped before Docker or applications. Audit opaque hash constants against the qualified parent and pinned proof before launching the copied runner.
- Keep canonical preimage hashes separate from already compiled SDK hashes. When chaining a correction, verify the canonical preimage before installation and verify the resulting payload against the final successful SDK inputs; a previous SDK payload is not automatically the canonical preimage.
- Separate preparation and execution stages with fail-fast shell handling (`set -e`) or explicit successful-return checks. A failed preparation assertion must stop the sequence before it can launch an unchanged duplicate SDK attempt. Preserve each actual failed or repeated attempt literally.
