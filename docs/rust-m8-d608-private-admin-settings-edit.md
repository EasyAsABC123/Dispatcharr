# Private direct administrator settings edit on d608ff75

Pinned Original and a private d608-derived Rust Main each completed an
eleven-request browser-form workflow in an isolated Compose project. The
workflow signed in, followed Core Settings links to one inert fixture row,
submitted its actual Save form with same-origin masked CSRF, followed the
302 to the list and observed the success message, reread the updated JSON,
and logged out. Each arm updated only its owned setting and added one
Django-format Value change audit row. The scoped Redis cache invalidated,
its version advanced during Save, and the separate control stayed intact.

The Rust edit listener bound to loopback in the owned network namespace
with no host ports. A fresh AIO process from the same image still returned
301 to /login without a session cookie. Both exact Rust Main generations
exited zero and every owned Compose role retired.

The edit selection belongs to this fixture image. Startup requires the
exact seeded row and its initial JSON. A successful Save changes that
JSON, so the same edit selection cannot admit the changed row on restart.
The scope covers one locally seeded row. Broader developer use requires
a persistent, explicitly owned scope and independent restart verification.

In pinned Django the cache callback runs before its SQL transaction
commits. The Rust path invalidates after the SQL setting and audit commit.
The successful Save replay leaves partial failure ordering open. The
private success message uses a short-lived signed cookie scoped to this
workflow. General Django messages, full M8 and performance remain open.
