# CoreSettings: historical Native component evidence

The inert Core7 prototype completed 32 real TCP requests against captured Source32
responses, with exact owned-setting and SQL/sequence effects. Its raw recorder
remains `passed:false`. The original controller exit 1 belongs to a later physical
observer failure; default-after and backend-after were unmeasured. The semantic
result does not imply that whole fixture passed.

The portable packet is under
`scripts/rust-contracts/core-settings-native-component/`. It contains bounded
credential-safe projections, a selected-trace verifier, corruption controls and
exact immutable-Git source reconstruction. Public verification covers response,
SQL, clock, socket and coverage predicates. Opaque binary cache and credential
fields retain original hashes and require private comparison; they are not
advertised as publicly redecoded effects.

Physical continuations retain separate output, cue and result identities. An
existing Native `StoreError::Database` maps to 503 with `Database unavailable`;
correcting an old controller expectation of 500 changes no runtime behavior and
establishes no Source error-status parity. No semantic request or already-passed
physical case is replayed to obtain a better aggregate.

The prototype shares the existing four writer permits and retains request owners
through physical SQL/cache completion. Main integration, ordinary REST full-User
allocation bounds, special coupled settings, forms, full M5 and performance remain
open. Historical source reconstruction preserves its old callback/test composition;
current integration must apply selected hunks and preserve newer registrations.

Seven finite physical ownership predicates now qualify across distinct historical
epochs. The original six controller failures are retained, followed by a passing
last-two-case continuation. Strict ACL restoration uses the separately observed
pinned Redis primitive; no runtime error classification was changed to satisfy
controller expectations. Public `verify_physical.py` checks those selected traces
without claiming that later audits fill the original missing default-after data.

history snapshots selected default Redis DB0, while Native authentication used
