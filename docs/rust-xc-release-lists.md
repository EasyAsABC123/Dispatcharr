# XC catalogue list release path repair

The earlier capability hook left the actual list writer and its dependencies behind test-only compilation gates. The immutable image56 source therefore rejected list execution even after Main opted in. This repair compiles the existing bounded writer for production, exposes its unchanged read-only output limit getter, and keeps shared parsing fields intact. Info-only modules remain test-only; four info-only enum variants have narrowly scoped non-test dead-code allowances. Default library constructors still disable list actions, while Main explicitly enables the two catalogue actions. No pool, permit, allocation limit, dependency or worker setting changes.

Two failed candidates are preserved: the first non-test build exposed the still-gated limit getter; the second strict check exposed unused info-only scaffolding. The corrected four-path candidate is checked independently against all 839 Rust and five coupled inputs. [Fresh workspace evidence](../scripts/rust-integration/xc-release-lists839/review.json) records formatting, whole-workspace compilation, strict all-target linting and **698 passed tests with 732 ignored**, across172 result blocks. All844 source hashes remain unchanged before and after each command; four actual test executables were copied outside the dependency cache only after all checks passed. These compile and component checks do not establish Main HTTP behavior, fresh-data refresh, full endpoint parity or new performance gains. A new immutable image and actual Main catalogue requests remain required. Image55 remains the selected measured application.
