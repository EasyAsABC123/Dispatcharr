# Original PostgreSQL backup restore warning

Pinned stock Original restored the same unmodified PostgreSQL v2 archive twice in a disposable AMD64 AIO fixture. With the original synthetic read-only role present, stock `pg_restore` exited zero and emitted zero warnings. After the fixture renamed that role, the second restore exited one and emitted exactly one warning. The observed text, including its trailing newline, was `pg_restore: warning: errors ignored on restore: 1`.

The independent audit matched the one PostgreSQL error to the missing old role name on the detached synthetic table grant. The renamed role had the same PostgreSQL identity. It retained the grant before the second restore and had no grant afterward. Both restores independently recovered the same synthetic row, returned successful signed task results and used the same stock prefork worker. The fixture retired the role and preserved the independent default database and template controls. The signed backup and two restore admissions returned 202, each signed status returned 200, and all three results joined to the actual broker publications and Redis task results. The archive remained byte-identical and contained only the database dump and metadata.

The execution, independent evaluation and outer owner exited zero. The exact scoped container IDs and their host process generations were absent. The owned network name and ID were absent, and all scoped Compose inventories were empty.

The warning came from the stock application's decoded child stderr boundary. The ordinary application log can truncate stderr, and this run captures no pre-decoding pipe bytes.
