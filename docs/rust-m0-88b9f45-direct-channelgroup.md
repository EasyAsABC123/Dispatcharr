# Experimental direct ChannelGroup read

The `direct-modeladmin-read` Cargo feature adds the read-only ChannelGroup list to a separate listener in Rust Main. The listener also requires `DISPATCHARR_DIRECT_ADMIN_BIND` with a numeric loopback address and nonzero port. The ordinary package leaves the feature off. The fixture used a private feature build and the existing PostgreSQL session data from an owned Original instance.

The list and HEAD endpoint check the current signing proof and expiry of a stock Django database session. In one read-only PostgreSQL snapshot they check active staff status and the current model permission, then return the first 100 rows in descending ID order. The native list template escapes stored names.

The paired Compose comparison used six sessions issued by the actual stock login form. Superuser, direct-view, and group-change grants returned 200. Missing and revoked grants returned 403. Anonymous, expired-session, and no-longer-staff cases returned the matching redirect. HEAD returned 200 and an unrelated Host value returned 400. The enabled and disabled cold projects retained public list 404 and history 301 responses. The disabled fixture observed connection refusal on the private port. Both projects verified exact teardown.

Earlier fixtures exited before completing the access cases. The second attempt located the fourth stock login at the configured three-logins-per-minute boundary. The passing fixture waited one complete 60-second window before the fourth login, using the same client identity. The [machine-readable record](../scripts/rust-integration/m0-88b9f45-direct-channelgroup.json) preserves the exact image, source map, and receipt hashes.

This qualification covers the default unfiltered list over existing stock sessions. Login issuance, session rotation, logout, filtered lists, history, and complete ModelAdmin coverage remain open. Original Dispatcharr, Django, and dependency authors and contributors retain full credit.
