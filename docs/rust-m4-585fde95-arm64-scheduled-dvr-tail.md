# ARM64 scheduled DVR final-packet failure on 585fde95

The fresh paired ARM64 exercise recorded the same scheduled DVR workflow used in the [AMD64 shutdown verification](rust-m4-585fde95-scheduled-dvr-shutdown.md). The stock Original run passed booking, signed HLS playback, operator stop, final audio and video decoding, and exact retirement. The Native run booked the same 70-second window, returned identical bytes for both signed HLS segment bodies, and decoded 200 video and 376 audio frames from those bodies. Its operator stop returned the same HTTP 200 response, and the recording row reported a successful remux.

The Native final MKV contained a corrupt H.264 access unit in its final video packet at 10.221 seconds. Strict decoding exited 183 on Lappy and on Beepboop using the exact same file bytes. The last correctly decoded frame was at 10.181 seconds. The Native application exited 0 with no OOM. Both Compose projects, the VM probes and all observed process generations retired.

The final stream-copy operation accepted the partial recording even though the strict playback check failed. The retained evidence leaves open where the malformed final access unit entered the capture or remux path. A follow-up will retain the actual terminal HLS playlist, its last segment and the recorder and remux process outcomes before cleanup. This run leaves ARM64 M4 media acceptance open.
