# Ordinary a8 native ARM64 on Docker Desktop

The ordinary `a8ea333d` application built natively on lappy's Linux ARM64
Docker Desktop daemon. All nine same-build component exports passed. The
non-root final image smoke checked 27 exact DRF assets. The source review
preserved 497 protected frontend and attribution inputs and 13 runtime
notices. Both optional SQLite build features were off.

A fresh private Compose project served HTTP 200 readiness and the exact
installed React index, and initialized 62 PostgreSQL application tables and
184 migration records with zero users. A second private project used the
same retained image for first-admin creation, JWT login and the protected
channel-group read. The five HTTP operations returned 200. PostgreSQL
showed one active admin with a recorded login, zero channel-group rows and
unchanged migration state. The response expectations came from pinned
Original contracts and its retained first-admin fixture.

Both Compose projects used a non-root ARM64 guest on a private internal
bridge. Each retired its five exact container IDs with empty project
inventories and no published host ports. An independent readback confirmed
literal 0 for the native build, readiness and authentication phases. The
image remained local. [Scoped receipts](../scripts/rust-integration/m10-a8ea333d-native-arm64-docker-desktop.json)

Full ARM64 browser, media and copied-data qualification, ARM64 SQLite
feature support and distribution remain open.
