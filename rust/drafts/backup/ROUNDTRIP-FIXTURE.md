# Queued disposable copied-database proof

This plan is unexecuted. Original Dispatcharr authors retain application credit. It is not a passing test, a proposed operation on a deployment database or permission to restore operator data. Parent owns all future image builds and coordinates any Cargo registration after the quiet window.

## Isolation and provenance

Use the pinned original image and a unique Compose project with loopback high ports, project-owned volumes, fixture-only database password and a unique lowercase run ID. Create three databases named `rust_probe_backup_<run>_a`, `_b`, `_c`; explicitly verify each name, database owner and disposable cluster identity before every destructive command. Never derive a target from an uploaded archive or allow `dispatcharr`, postgres, template0 or template1 as a restore target. The supervisor may connect to postgres only to create/drop these exact owned names, using quoted identifiers. Keep an owned-name registry for cleanup and collect its outcome even on failure.

Capture original source archive/hash, native component source/hash/test executable, probe-tool snapshot, exact PG client ELF/library manifest, container IDs and database server/client versions. No actual environment values, JWT keys, passwords, provider credentials or dump bytes belong in committed evidence. Raw ephemeral archives/fixtures stay ignored. Reports contain only redacted scalar counts, statuses, canonical manifest hashes and report hashes.

The source helper must start a **new original process** with POSTGRES_DB set to the exact owned target before Django setup; do not repoint a running web service's global connection pool. Run original services/tasks unmodified, with only disposable fixture settings such as BACKUP_ROOT and database selection. A source helper can call the actual restore task body to include `migrate --noinput`; bypassing the API/Celery transport does not establish durable job or browser parity.

## Data and roundtrip sequence

1. Create A/B/C using an explicitly fixture-authorized administrator, and migrate only A with the original command. Seed owned original ORM fixtures: active/inactive users with current default password hashes, API keys, provider/channel/stream/profile relationships, IDs, integral/float/string/null JSON values, groups/memberships, override relationships, settings and migration rows. Include nonempty sequences and next-ID witnesses. No fake success rows or live upstream requests.
2. Write small logo/upload/recording/plugin sentinel files into a separate owned media volume and point fixture DB rows at them. Record private per-file hashes and reference counts. Keep C's corresponding media root empty to demonstrate the DB-only archive boundary. The fixture must never infer that restored database references imply copied files.
3. Capture a read-only logical-data manifest before authentication side effects: selected fixture rows/relationships, exact password/hash/API-key fields hashed privately, sequence values, schema/index/constraint names and migration history. Exclude physical OIDs, relfilenodes, owner identity intentionally changed by `--no-owner`, and archive timestamp/compressed-byte nondeterminism. Each ignored field must be declared. JSON canonicalization must preserve numeric/string/boolean distinctions rather than use Python `==` alone.
4. Original create from A → native component restore into B. Inspect actual ZIP member names, compression/ZIP64 properties and metadata types. Compare B's logical manifest with A, then exercise original/native read APIs and credentials against B with the same independently configured deployment secret. No extra mutations should be hidden by manifest normalization.
5. Native create from B → original **full restore task** into C, including migrations. Compare C's pre-login logical manifest and next-ID behavior. Exercise the original and native account/channel/provider reads, password/API-key authentication and legacy references. Track any explicitly expected login/audit/token-table changes separately. Do not compare raw pg_dump or ZIP hashes as an equality oracle: the dump/ZIP has volatile metadata.
6. Verify that C has preserved media path references while its initially empty media volume remains empty. Demonstrate the expected missing-file result, then copy only the separately owned sentinel media fixture and demonstrate success. Record this as a separate file-transfer gate, not a capability of the ZIP.
7. Repeat token interoperability with the same secret, then a different fixture secret to verify expected signed-token rejection. Never add the secret file to the archive just to make tests pass. API/password credential preservation is independent of JWT deployment-key continuity.
8. Remove all owned databases, files and Compose resources. Record failures in cleanup separately from application failures. A failed restore must never be retried against a nonowned database to obtain a passing report.

## Failure and resource gate matrix

| Family | Actual gate, not an inferred assertion |
| --- | --- |
| PostgreSQL result policy | Real success; invalid custom dump after schema cleanup; nonzero warning-only outcome; fatal/could-not-connect result; partial restore followed by original migrate. Compare logical data, not merely returned status. |
| Metadata/archive | Missing/invalid/nonobject metadata; missing selected dump; engine mismatch; format/version ignored by Source; duplicate names; stored/deflated/ZIP64; extra members; CRC/truncation; relative/absolute/parent-path selections. Unsafe cases operate only in the owned extraction sandbox and remain explicitly outside native accepted scope until a policy is agreed. |
| Environment/TLS | Password present/absent, removal of inherited PGSSL variables, configured verify-full/CA/client cert/key, hostname verification and failed auth. Fixture-only certs and no external services. |
| Child ownership | Rust/shell helper tools in the disposable component test fixture emit bounded/unbounded diagnostics, split critical strings at every chunk boundary, return all relevant exit classes, emit invalid UTF8, sleep, fork a pipe-holding descendant and produce oversized files. Kill/wait and pipe-thread completion must be witnessed after timeout, explicit cancellation and dropped observer. No CPython is needed in the packaged native runtime. |
| Admission/memory/disk | One admitted worker; next request rejects busy; observer drop retains owned task; cancellation joins/reaps; disk and metadata caps reject before unbounded allocation; live RSS/PSS/threads/FDs/process count return to baseline. Original valid copied-data workloads use equivalent resource scope. |
| Lifecycle | Native pool/cache/session quiescence and recreation around restore; old schema upgrade and incompatible archive failure. Current empty-only initializer is not an upgrade engine. |
| Jobs/browser | Future persisted worker202/task-token/status contracts, restart recovery, unchanged React download/upload/restore polling after authentication changes, schedule/timezone/retention. These cannot be claimed by the component roundtrip alone. |

Fake command helpers can validate supervision/diagnostic policy but cannot substitute for the real PostgreSQL A→B→C interoperability proof. Actual success/failure logs and fixture source snapshots must be retained. Once functional gates pass, measure the full app+native worker+PostgreSQL-tool service scope with equivalent input, archive size and media policy; do not infer a CPU/RAM reduction from a streaming implementation alone.
