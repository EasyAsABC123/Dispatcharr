# Unregistered native backup component draft

Original Dispatcharr authors and contributors retain full application credit and AGPL licensing. These files were written during a performance quiet window. **They have not been registered, compiled, formatted, executed or accepted.** No Cargo manifest, lockfile, application route, durable worker or Docker recipe was changed.

- `backup.rs`: standalone synchronous component using a single owned admitted worker, bounded subprocess diagnostics and file streaming. Intended cached dependencies on later registration: serde/serde_json, zip9.5.0 with existing deflate feature, uuid/v4 and libc. It needs no Python or Tokio runtime. A caller supplies the Source-compatible system/pytz/ZIP clock conversions; it does not approximate them using the host timezone.
- `collect_pg.py`: guarded build-stage draft collecting the **actual** `/usr/lib/postgresql/17/bin/{pg_dump,pg_restore,psql}` ELF files from the pinned original image into `/opt/dispatcharr-postgres`, their loader/library closure, optional NSS/OpenSSL providers, public PG support data and available copyright/common-license notices. It deliberately bypasses Debian's possible Perl `/usr/bin/pg_*` wrapper. No interpreter, credential, deployment secret, database directory or private key is copied. Nothing has been collected or built yet.
- `ROUNDTRIP-FIXTURE.md`: disposable copied-database acceptance plan.

## Implemented draft scope

Creation invokes `pg_dump` with the original connection arguments, custom format, verbose flag and temporary output file. It writes only `database.dump` and `metadata.json` in a DEFLATE/ZIP64 v2 archive. Filename timezone and ZIP entry timestamps come from an explicit future clock adapter; metadata UTC time is requested after the dump. Archive opening preserves the original direct truncate/partial-file behavior rather than silently changing it to an atomic publish.

Restore accepts only an explicitly authorized `rust_probe_backup_*` database name. The archive is preflighted before library metadata allocation; metadata and the selected dump are streamed under caps. The selected file must stay a normal relative path. It invokes the original public-schema cleanup SQL and `pg_restore --no-owner`; nonzero restore statuses without `fatal` or `could not connect` in the entire drained stderr are warnings, matching the original component's unusual policy. This is **not** evidence that the restored data is complete. It does not run migrations or report application task completion.

Commands inherit environment except the same password/TLS variables stripped and reconstructed by the original helper. Password never enters argv. A dedicated process group, explicit deadline/cancellation, hard child file-size limit, kill/wait ownership and bounded pipe draining are drafted. Stderr retains only a private capped prefix and byte counts; critical-message search spans chunks, and UTF8 validity is checked because the original uses text-mode subprocess capture. Public errors contain stage/status categories, not credentials or raw diagnostics. The implementation needs actual cancellation, reader-thread and subprocess-reaping tests before any reliability claim.

The admission object allows one owned worker and no unbounded waiting queue. Dropping its thread handle leaves admitted work running, analogous to a disconnected client observing a queued job, but **there is no durable queue or restart recovery**. The caller owns explicit cancellation and joining. Scratch directories are created with Unix0700 and removed on scope exit. Archive/data copies use8KiB buffers. Directory metadata is capped before constructing ZipArchive. Default disk caps are128GiB per dump/archive, metadata64KiB,128 ZIP entries,8MiB central directory and64KiB per diagnostic prefix. Limit configuration itself restricts retained-memory caps. These bounded operating limits are deliberate differences from unbounded original input behavior.

## Acceptance blockers

Compilation/API checks, actual original ZIP interoperability, clock/DST behavior, command statuses, diagnostics across chunk boundaries, corrupt/duplicate/ZIP64 input, disk-full/limit cleanup, held-pipe descendants, timeout/cancellation and retained-memory measurements are all pending. The collector must prove loader conflicts, PG17 versions, no missing dependencies/interpreters and notices. Copying ldd libraries is insufficient proof for DNS/TLS/GSS/LDAP/encoding/provider behavior; those require packaged integration vectors. Provider search paths/configuration may need explicit handling; copying a module does not prove libcrypto finds it. Never copy operator secrets or global host configuration to make a test pass.

Malformed archive/path restrictions, ignored extra members, capacities, sanitized component errors and cancellation are explicit scope differences requiring original boundary captures. The original can extract arbitrary extra members and trusts its metadata-selected path more broadly; this draft deliberately does not expose those semantics through a production route. SQL migration upgrades, pool/cache/session lifecycle after restore, durable task202/status/token records, SQLite, scheduler/retention, upload/download APIs, same-second concurrency across replicas, CLI and browser backup workflows remain separate prerequisites.

The original DB-only ZIP excludes logos, uploads, recordings, plugins, Redis and `/data/jwt`. Preserve database references, and document/verify separately managed files and deployment secrets. Do not claim a database-only roundtrip transfers those files.
