# Programme byte index

All application and algorithm credit belongs to the original Dispatcharr authors and contributors.

Evidence 86 captures the original index task on 24 synthetic cases. Evidence 87 compares the bounded raw scanner with 21 original index maps, including every original HTML5 named entity, numeric references, invalid UTF-8 replacement and Python strip behavior, 8 MiB chunk boundaries, the 4,096-byte start-tag boundary, and the ten-offset/interleaved-channel rule. Four pure guards cover key capacity, cancellation before work, descriptor continuity after atomic path replacement and file-size capacity. Task SQL, file leases, missing-file handling and deferral remain separate gates in that evidence.

The scanner preserves the original literal behavior. It records raw `<programme` markers inside comments, accepts the slash tag follower, finds `channel` inside an attribute name such as `notchannel`, leaves the previous channel unchanged when an attribute is missing, and can record an unclosed final start tag. It does not replace the byte scanner with a normal XML document parser or require a complete XML footer. It resets and validates the same opened descriptor rather than reopening a path after validation.

The stored result is exactly `{"channels": {"tvg_id": [byte_offsets]}, "interleaved_channels": [sorted_ids]}`. Offsets refer to original bytes before decoding. Channel IDs use replacement UTF-8 decoding, the shared pinned Python HTML5 unescape helper, and original strip rules. The scanner retains at most one 8 MiB chunk plus a 4 KiB tail and a bounded index map. Its default limits are 100,000 keys, 64 MiB accounted state, a regular input below 4 GiB, and five million encountered tags. Larger supported configurations remain bounded; no full-source buffer is used.

The post87 `IndexService` draft supervises blocking scanning, file leases and a private transactional writer. It reserves scanner/tree/JSON/driver memory credits before heavy work, bounds queued waiters with job admission, checks JSON size before constructing its SQL tree, and releases large driver buffers with the private writer. Cancellation before the commit check rolls back and retains guards through actual rollback and Redis release. The commit check is a cancellation boundary, not a distributed Redis/PostgreSQL fencing guarantee. Evidence 90 compares all24 original task outcomes and three physical scenarios: memory waiters stay bounded while a blocked writer retains ownership, canceled writes roll back before release, a replacement owner observed before commit prevents a stale write, and an explicitly small wire budget preserves the previous index. Index deferrals use the original five seconds; failed attempt88 incorrectly reused the refresh task's15 seconds and remains preserved. The exercised profile reserves32 MiB total with1 MiB state/wire budgets and two admitted jobs. Credits are conservative enforced reservations, not process RSS. The service is not app-wired.

Lookup at stored offsets, interleaved forward fallback, current-program API integration, actual durable index dispatch and performance acceptance remain open. The existing task-lock implementation also needs an outage/deadline test: a renewal awaiting a missing reply currently cannot prove a local TTL-expiry signal. Existing owner-checked release proofs do not imply that outage guarantee.
