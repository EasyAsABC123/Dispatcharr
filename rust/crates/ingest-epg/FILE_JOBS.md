# Local-file refresh orchestration

All application and algorithm credit belongs to the original Dispatcharr authors and contributors.

`FileJobRunner` is an app-unwired component. It retains bounded job admission and the caller's guard while running the original refresh/file lease sequence, index invalidation, download-complete notification, channel pass, programme pass and child dispatch boundaries. It uses the same `task_lock_refresh_epg_data_{id}`, `task_lock_epg_source_file_{id}` and per-channel counter keys. Existing Source owners prevent native work. Native owner tokens and owner-checked release preserve replacement owners.

The file lease is nested inside the refresh lease. Parser, SQL, cache and publication operations retain that context through physical completion. After their final references disappear, an owned task awaits the actual Redis release reply. Only `release_owned() == true` permits index dispatch. Index dispatch observes the file key absent and refresh key still present; the final source timestamp and series-rule dispatch follow. Caller cancellation requests cancellation of the owned worker; shutdown reports false while physical work or lease release still holds its slot. Lease loss also requests cancellation. This is cooperative cancellation and owner fencing, not a PostgreSQL/Redis distributed transaction.

The fixed ordinary-local-file corpus passes 14 cases against the actual original task: successful, empty, unmapped and incomplete guides; missing files; inactive/dummy sources; held refresh/file keys; active or malformed counters; exhausted deferrals; and missing sources. It compares original publications with database/Redis state at each boundary, final programme/channel state, generation changes and captured child dispatch. The valid gzip case is preserved as Source-only in evidence 71/72. Evidence 73 compares all 15 cases, adding fresh valid gzip extraction with an explicit synthetic MEDIA_ROOT shared by original and native fixtures. Native extraction uses a uniquely owned incoming output, validates completeness and promotes it before saving the extracted path. Invalid inputs and old-good-cache error/replacement semantics remain separate gates.

Evidence 72 adds three physical scenarios. Blocked PostgreSQL retains the refresh key, caller guard and job slot after caller cancellation; after unblocking, no parser/swap/index dispatch follows. A WRITE-paused Redis server retains both keys and the guard until the actual file-release reply, and shutdown prevents index dispatch. Replacing the file owner immediately before release returns false, preserves the successor and its TTL, and prevents index/series dispatch. Direct true/false release results and unchanged legacy `release()` behavior are also checked.

Limits are explicit: one to four admitted jobs, existing bounded channel/programme/report/cache adapters, bounded source metadata/counter decoding, and a bounded release wait. A timed-out waiter does not release physical work. The dispatcher interface must retain the supplied context through its actual queue reply. The test dispatcher observes index/series/defer boundaries and checks that no late mappings appeared; it does not execute those child tasks.

Evidence 82 adds enabled automatic logos and the original property-type failure after channel completion, comparing all 17 local-file task cases and all three physical guards. This is still observed child dispatch, not child execution.

Evidence 75 reruns all 15 cases and all three physical guards in an immutable component-only Docker image, as UID 65532 with a read-only root, 512 MiB memory, two CPUs and 128 PIDs. This image preserves accepted73 runtime bytes and adds only its test packaging and credit/license files.

Remote download, invalid/oversized compressed input, old-cache replacement/error behavior, transient database retries and general exception text, orphan periodic-task cleanup, newly mapped child execution, index generation, series evaluation, durable task queues, the HTTP import API and app wiring remain open gates. The component must not be advertised as full refresh-job parity or a performance result.
