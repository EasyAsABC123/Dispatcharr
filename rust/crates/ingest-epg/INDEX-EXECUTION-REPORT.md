# Detailed index execution observations

Original Dispatcharr authors retain all application/algorithm credit. This additive component does not attach an exception writer or change application startup.

`IndexService::build_report_with_dispatcher(request, caller, dispatcher)` preserves the old service's admission and supervised physical work. Its outer `Err(ImportError)` is an operational admission/setup/panic result. A returned `IndexExecutionReport` has three independent observations:

- `operation`: a normal `IndexOutcome`, or a typed stage with the original `ImportError`/bounded task-lock cause. Missing source/file remain normal. Malformed XML, lossy UTF-8 and empty files really write their exact partial/empty index before `Written`.
- `commit`: `NotWritten`, `Written`, or `Ambiguous`. Commit is marked ambiguous before awaiting its physical reply and marked written only after successful commit.
- `release`: not acquired, settled acquisition cleanup, released, not owner, command error, timed out, or unavailable runtime. A command error carrying I/O is not evidence that remote DEL did not execute. TimedOut means cleanup still owns the caller/admission until its actual reply; it is not a Python exception.

An operation can be `Written` while release failed. Source136 demonstrates that the task can then fail with an already committed index and a remaining lock. Conversely, an early directory error has no new index write but still releases its acquired file lease. Do not derive a task terminal result from the operation axis alone. Both operation and cleanup errors are retained; exact combined-failure exception precedence remains a separate original gate.

The existing `build`/`build_with_dispatcher` APIs keep their prior coarse errors and non-regular-file guard. Only the detailed Linux path distinguishes directories as EISDIR21; FIFO/device policy remains a bounded operational guard. The optional SourcePathContext remains unchanged.

TaskLocks adds `acquire_detailed`, `acquire_retained_detailed`, and `TaskLease::release_owned_detailed`. The retained form keeps caller ownership through the actual SET and owner-checked cleanup, including a dropped receiver. SET I/O ambiguity is settled through physical CAS cleanup before returning an acquisition error. Coarse APIs retain their previous mappings. Redis kind, server code (up to64 bytes), I/O kind/errno and detail (up to16KiB) are retained; oversize flags prevent silently claiming complete source diagnostics. No credential-bearing connection URL is stored in these causes.

These are transport and stage facts, not Python exception inference. Connection endpoint identity, exact network error arguments, original client-initialization None handling, arbitrary SQLSTATE rendering, result traceback generation and task-result publication require their separate compatibility gates. Source138 shows initialization retry failure becomes AttributeError, while busy child publication becomes Kombu OperationalError. They must not be collapsed into the cached-client errors from136.

No performance gain follows from these functional observations.
