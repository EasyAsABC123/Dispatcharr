# Current-programme lookup adapter component

Original Dispatcharr authors and contributors retain all application and algorithm credit.

`src/current_lookup.rs` is registered as a component against the shared Store interface. Frozen100 passes 17 literal Source outcomes, six explicit unsupported malformed-shape boundaries, two physical resource scenarios, 24 unit tests and strict all-target Clippy. The accepted file component is recorded separately in `CURRENT_FILE.md`. No application request uses this draft.

The Store callback must execute only after its original ordered EPG metadata/programme transaction has rolled back and released the pooled connection. Pass a source/EPG snapshot and an owning caller guard. Source samples a fresh clock after source type, TVG and file-existence guards, then reads the index fresh for each EPG entry. Missing row, SQL NULL and JSON null request a durable index task and produce parsing only after accepted dispatch. A missing channel produces no task. Never inject a process-only dispatcher into the application.

The draft bounds admitted jobs, memory credits, read buffers, target-index bytes, offsets, native parsing and serialized responses. Its owned task retains caller/admission credits through actual PostgreSQL replies, blocking file work and connection close even after the requester cancels. Response Bytes retain credits for their actual Vec capacity through clones; parser working credits return when physical work ends. Memory admission fails capacity instead of waiting for bytes held by earlier DTOs in the same ordered response, avoiding a response-assembly deadlock. Shutdown signals cancellation, then reports whether physical work finished by its deadline; it does not claim physical work stopped merely because a waiter timed out.

The index query projects one TVG's offsets and membership rather than decoding the full source index. This requires actual Source differential cases for missing/null/malformed shapes and supported Source-produced indexes. It does not establish general malformed-index compatibility. Tests must prove a changed index is observed after the fresh clock sample, concurrent deletion dispatches once per original invocation, and blocked SQL/canceled file workers retain their caller resources.

Before app wiring, preserve Source's two independent opens: `_read_programs_at_offsets` opens once for its offsets; after a miss, interleaved `_scan_from_offset_for_tvg_id` opens the path again. The existing pure descriptor API pins one inode across both operations and its current proof covers stable files only. The draft adapter now uses the additive file-factory API to reopen at the forward boundary; six controlled atomic replacement/deletion/open-count cases passed in the separate frozen98 file-component gate. The SQL service has its separate frozen100 component proof. Same-open-descriptor validation still applies within each individual helper. File/index refresh schedules must be tested as allowed Source outcomes rather than treating stable fixture equivalence as concurrent-refresh acceptance.

Remaining gates include a bounded source-path/cache-path snapshot, fresh clock/index semantics, exact missing-index dispatch, isolated PostgreSQL cancellation and memory/body clone tests, malformed stored values, Source interleaved timeout conversion, and current API response ordering/body limits. No fresh performance or application acceptance is implied.
