# Native job transport component — app unwired

Original Dispatcharr authors and contributors retain full application/integration credit and AGPL licensing. This crate supplies no application router, production worker constructor, scheduler or HTTP202 response. Its new CreateBackup worker is restricted to explicit copied-database fixtures.

The original supported protocol2 writer covers captured backup-create and safe-name restore tasks. The separately tested immediate-index protocol is described below. It preserves decoded Source header/property/body values and identity relations. IDs/reply targets/origin vary and JSON whitespace/escaping is not claimed byte-identical to Python. Quote/control/traversal filename shapes, other task families/routing/ETA options remain unsupported; this is not a general Celery client.

The bounded metadata reader uses the actual Source result prefix and known PENDING/STARTED/RETRY/SUCCESS/FAILURE states. It validates requested task identity, byte/tree/string bounds and observed builtin ValueError/KeyError exception records. Captured Kombu date/datetime/decimal/bytes/base64/UUID values remain explicitly encoded with a tag inventory: no Python emulation or HTTP projection is claimed. **CelerySUCCESS is not application success**: an original failed backup service can return a failure dictionary under SUCCESS. Tagged dictionaries must not be passed blindly to the separate status mapper.

`Jobs::connect_fixture` is deliberately fixture-only: explicit guard environment, copied `rust_probe_backup_*` database, loopback fixture password and Redis DB8/result DB9 on the same endpoint. There is no production constructor. Publication uses bounded atomic queue/type/binding checks and LPUSH; the fixture Create worker retains unsupported queue heads without consuming or reordering them. The existing bounded supervised Redis transport retains physical command/owner leases after caller timeout/drop. Ambiguous publication returns the task ID without success or automatic retry. Shutdown closes admission then waits for all own physical leases; a failed drain does not release those owners early.

Five pure protocol/decoder/Create-envelope controls pass, including24 normalized actual Source metadata records. `scripts/rust-job-contracts/verified-native-source-interop-1.json` binds the frozen first component binary/source and65 observations with a real original worker on a copied database. NativeCLI publication survives process exit; Source creates the archive and native reads its result. InvalidZIP restore was published to Source, which fails before schema replacement. This does not establish native handler execution or production restore authority.

Two explicit ignored realRedis resource tests are drafted in `tests/resources.rs`: accepted LPUSH with held reply/timeout/retained caller and failed drain, and canceled result caller with shutdown waiting for a held physical reply. They now pass against actual Redis in the owned fixture, with independent confirmation of server-side LPUSH before a withheld reply. `verified-native-job-resources-1.json` binds the frozen source/binary and actual logs. They are ignored by default only because they require explicit disposable services; the fixture runner executes both with `--ignored`. No silent skip or hypothetical semaphore test substitutes for actual delayed replies.

Remaining gates include broader resource/backend-fault cases, queue-capacity/WRONGTYPE/corrupt metadata recovery, broader Source worker interoperability, idempotency/visibility recovery, production execution, restore quiescence and scheduler coupling. Original capture evidence remains under `scripts/rust-job-contracts/`; runtime/job APIs must stay disabled until their own acceptance sequence passes.


The fixture-only Create worker now executes the existing bounded PostgreSQL/archive service on a supervised blocking task. It validates the complete captured Create envelope before an atomic compare/pop early-ACK boundary. It intentionally does not implement general Kombu reservation/unacked/priority/ETA recovery. A task and its caller keep the single worker admission through archive execution and the physical result reply. Canceling the outer caller detaches accepted work; warm shutdown closes new admission and drains accepted work before closing result commands. An ambiguous claim/result reply is not an automatic retry.

`source_create_worker.py` uses an actual original producer, status reader and PostgreSQL17 client tools on a nonempty copied database. The separately frozen second fixture passes24 checks: successful native archive/result readback through Source,3600TTL/backend separation, unsupported Restore head retention, earlyACK/PENDING while handler held, worker-process kill before archive creation, replacement/no immediate replay, and Source ZIP/readback compatibility. The injected service-failure control compares the original wrapper's returned dictionary separately from actual archive errors. **Native archive error strings are bounded diagnostics and are not Source message parity.** UTC fixture clocks do not establish all configured timezone behavior. No destructive restore or application202 route runs.

The two new Create physical-owner tests use held actual Redis result replies and a deliberately blocked handler. They require explicit copiedDB/Redis services and remain ignored in ordinary unit runs; execution evidence is separate from the first transport resource pair. General hard-kill child/spool recovery, one-hour visibility behavior, scheduler, index tasks and production routing remain open.
