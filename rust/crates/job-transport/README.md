# Native job transport component — app unwired

Original Dispatcharr authors and contributors retain full application/integration credit and AGPL licensing. This crate supplies no application router, native task worker, scheduler or HTTP202 response.

The supported protocol2 writer covers captured backup-create and safe-name restore tasks only. It preserves decoded Source header/property/body values and identity relations. IDs/reply targets/origin vary and JSON whitespace/escaping is not claimed byte-identical to Python. Quote/control/traversal filename shapes, other task families/routing/ETA options remain unsupported; this is not a general Celery client.

The bounded metadata reader uses the actual Source result prefix and known PENDING/STARTED/RETRY/SUCCESS/FAILURE states. It validates requested task identity, byte/tree/string bounds and observed builtin ValueError/KeyError exception records. Captured Kombu date/datetime/decimal/bytes/base64/UUID values remain explicitly encoded with a tag inventory: no Python emulation or HTTP projection is claimed. **CelerySUCCESS is not application success**: an original failed backup service can return a failure dictionary under SUCCESS. Tagged dictionaries must not be passed blindly to the separate status mapper.

`Jobs::connect_fixture` is deliberately fixture-only: explicit guard environment, copied `rust_probe_backup_*` database, loopback fixture password and Redis DB8/result DB9 on the same endpoint. There is no production constructor. Publication uses bounded atomic queue/type/binding checks and LPUSH; no consumer removes unrelated messages. The existing bounded supervised Redis transport retains physical command/owner leases after caller timeout/drop. Ambiguous publication returns the task ID without success or automatic retry. Shutdown closes admission then waits for all own physical leases; a failed drain does not release those owners early.

Four pure protocol/decoder controls pass, including24 normalized actual Source metadata records. `scripts/rust-job-contracts/verified-native-source-interop-1.json` binds the frozen first component binary/source and65 observations with a real original worker on a copied database. NativeCLI publication survives process exit; Source creates the archive and native reads its result. InvalidZIP restore was published to Source, which fails before schema replacement. This does not establish native handler execution or production restore authority.

Two explicit ignored realRedis resource tests are drafted in `tests/resources.rs`: accepted LPUSH with held reply/timeout/retained caller and failed drain, and canceled result caller with shutdown waiting for a held physical reply. They now pass against actual Redis in the owned fixture, with independent confirmation of server-side LPUSH before a withheld reply. `verified-native-job-resources-1.json` binds the frozen source/binary and actual logs. They are ignored by default only because they require explicit disposable services; the fixture runner executes both with `--ignored`. No silent skip or hypothetical semaphore test substitutes for actual delayed replies.

Remaining gates include broader resource/backend-fault cases, queue-capacity/WRONGTYPE/corrupt metadata recovery, broader Source worker interoperability, idempotency/visibility recovery, native execution, restore quiescence and scheduler coupling. Original capture evidence remains under `scripts/rust-job-contracts/`; runtime/job APIs must stay disabled until their own acceptance sequence passes.
