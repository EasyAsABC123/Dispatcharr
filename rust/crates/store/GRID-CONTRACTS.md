# Guide grid components

All application credit remains with the original Dispatcharr authors. The date parser port also retains the original Django BSD license in [third-party/DJANGO-LICENSE](third-party/DJANGO-LICENSE).

The frozen component proof `scripts/rust-epg-contracts/verified-grid-window-components-17.json` compares 861 actual original helper cases: 557 windows, 34 profile selectors, 117 dummy spans, 48 stored-row projections, 98 batch encodings and seven chunk-count boundaries. Three Rust tests and strict Store all-target Clippy pass. This subset is independent of the packaged image23 checkpoint.

Window handling preserves absolute/relative precedence, last repeated query parameter, Unicode decimal integers, bounded day selection, timezone offsets including fractional seconds, and captured original exception classes/messages. Original local offset representation is retained separately from UTC comparisons. Golden cases cover the captured grammar; exhaustive Python datetime acceptance remains unclaimed.

Grid rows use the original Django millisecond datetime representation, separate from programme-detail microseconds. Batch encoding is capped at 500 rows and 16MiB per frame. Those bounds do not establish HTTP backpressure or query bounds: SQL visibility/overrides, dummy programmes, cancellation, database cursor lifetime and wire streaming must pass their own gates before application attachment. No grid HTTP parity or performance gain is claimed by this component proof.

The later `verified-grid-entity-components-24.json` proof compares all22 successful guide cases from the40-case original view corpus: exact metadata/channel order, stored-row projection and full JSON entity bytes including standard dummy programmes. It uses the measured Source history policy and a pinned clock. The other18 view cases still require native HTTP permission/error gates.

A narrow effective-EPG join changed observable channel order. A second projection with guards/casts also changed the query plan. The accepted metadata component preserves the original full projection and join graph, with unique native column aliases. A same-snapshot EXISTS preflight bounds Source JSON/text before the unchanged-width projection. Metadata uses a read-only repeatable-read transaction; per-field limit64KiB, metadata charge16MiB,50K rows, and a2s statement timeout are explicit native capacity bounds. Stored rows have a1MiB SQL guard,50K-row cap,16MiB conservative batch charge and32MiB aggregate frame limit. An overload fails explicitly; no rows are silently omitted.

The complete entity component lives in `output-http::epg_grid`, reusing shared standard dummy templates. It has no application route. Exact full-body bytes are accepted for the22 captured successful cases; native internal frame boundaries are not a Source chunk-boundary claim. Custom dummy rules, offset-sensitive dummy windows, extreme dates, HTTP authentication/errors, admission/body lifetime and cancellation/shutdown remain open. Separate metadata/stored snapshots also require concurrent-update consistency tests before attachment.

The post-image24 `verified-grid-datetime-components-25.json` proof adds7,189 actual original compiled-Python/Django ISO vectors and regresses all861 earlier helper cases. Four tests and strict Store all-target Clippy pass in a fresh frozen tree. Initial broader audits found962 mismatches; those findings remain preserved. The corrected primary parser mirrors [CPython compiled ISO handling](https://github.com/python/cpython/blob/v3.13.9/Modules/_datetimemodule.c), including numeric week separators, compact digit-only fractions and UTF8-byte-length/trailing-byte bare dates. It then follows Django's regex fallback and exception behavior. The compiled parser and `_pydatetime.py` differ; the actual original compiled implementation is the oracle. No input/output normalization is applied.

Original Python copyright and licenses are retained in `third-party/PYTHON-COPYRIGHT`; future app packaging copies that notice beside the existing Django notice. This packaging line awaits its next app-image build. The parser correction is independent of immutable image24 and does not claim exhaustive Python grammar, native grid application attachment or a performance gain.
