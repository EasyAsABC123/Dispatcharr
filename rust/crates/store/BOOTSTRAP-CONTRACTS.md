# Native first-admin and clean-install gates

All original application credit remains with Dispatcharr authors and contributors. Source contracts are `apps/accounts/api_views.py:initialize_superuser`, `dispatcharr/utils.py:setup_ip_allowed`, Django's UserManager and the pinned original migrations.

The existing configured-system status path is already source-verified. Any account at level10 or higher closes bootstrap, including an inactive account. Once closed, the original plain Django view ignores method, credentials and request body and returns `{"superuser_exists":true}`. No JWT or API-key preflight belongs on this route.

On an existing migrated schema with no admin, GET and non-POST methods report the resolved client IP and setup permission. POST checks the setup network before reading JSON: default private/loopback networks, or the exact single IP in `DISPATCHARR_SETUP_ALLOWED_IP`. This gate is independent of the UI network policy and shared login budget.

The original POST calls `json.loads(request.body)` and UserManager.create_superuser directly. It does not apply the DRF UserSerializer's safe-credential regex, password whitespace trimming, email validation or password-strength validators. Empty/falsy username or password gives400; malformed JSON and UserManager/database exceptions give500 with an error string. Username NFKC and email-domain normalization, default flags, short/whitespace passwords, inactive-existing-admin closure, duplicate nonadmin usernames and configured-body bypass are covered by the25-case original/native source gate.

First-admin API acceptance is not clean-install acceptance. The app now has an explicit fresh-database initializer, default off, with source-pinned tables and default rows. Native clean install requires a source-pinned schema/default-data manifest, an explicit fresh-database guard, actual PostgreSQL application and verification without Django writing the native database, then first-admin/login/React initialization checks. Existing migrated databases must remain unchanged. Migration upgrade/rollback and default-data provenance are separate gates; no Python bootstrap sidecar should be silently called a Rust clean install.

Password inventory from the pinned original runtime: PBKDF2 SHA256 and SHA1 work; hashlib Scrypt is available. Argon2PasswordHasher and BCryptSHA256PasswordHasher classes are listed by Django defaults but their Python packages are absent in the pinned image. Introducing successful authentication for those unavailable families would change source behavior. Native Scrypt now passes actual original hash/upgrade cases and packaged image16 password regression; bounded allocations/work and blocking-worker admission remain explicit implementation limits.


Current component evidence: `verified-first-admin-source-2.json` passed25actual original/native cases on the migrated schema, including short/whitespace passwords and Unicode email behavior. `verified-nfkc-dataset-2.json` records all-scalar Unicode15.1 normalization/lowercase comparisons. `verified-native-schema-sql-4.json` separately passed native62-table/498-default/184-migration creation, original pg_dump equality, existing preservation and concurrent fencing. Image16 separately passed explicit initialization, actual first-admin/login/JWT persistence and restart using only official PostgreSQL/Redis and the Rust candidate. Its actual React test failed on missing deferred logo/filter-option reads, so clean-install browser acceptance remains open. Those reads pass44 original/native source cases separately; an immutable image and browser rerun are required.


`verified-native-clean-install-image17-2.json` closes the pinned fresh-install/browser/restart slice: the unchanged React first-admin form, login, all16requiredAPIresponses including deferred logos/filter-options, zero API errors/exceptions, verified stored JWTs and restart persistence passed against official PostgreSQL17/Redis with no Django service. Image16 failure remains preserved separately. Populated workflows, legacy upgrades, image uploads/cache delivery and native refresh/EPG jobs remain separate gates.


Reproduce the immutable native browser gate with `python3 scripts/rust-integration/run_clean_install.py --candidate-build-manifest artifacts/rust/candidate-build-m5-react-reads-image17-1/build.json --output artifacts/rust/another-empty-native-run`. The output directory must be empty; the selected build manifest must identify a successful local image. The script snapshots its Compose/browser tools, selects loopback fixture ports, starts the three pinned services, uses actual Chromium forms, records sanitized checks and cleans all project services/volumes. It writes no SQL data itself. A Redis-only fixture lock prevents unrelated external IP lookups; separate original/packaged IP gates verify that worker. The browser executable and screenshot digests are retained in the report.
