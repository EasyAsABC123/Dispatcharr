# XC late ErrorResponse/Ready ownership component

Five producer finishers now wait for PostgreSQL Ready using `ping`, then await
return to the existing pool before releasing the existing request owner. The
ordinary queries, transaction boundaries, pools and memory allowances are unchanged.

Ten finite Native physical predicates were qualified from retained captures: five
producers with explicit observer-task abort and with the existing 15 second logical
deadline. Every fault follows one successful real Native gateway prelude on the
same peer and prepared backend. This is not TCP-disconnect cancellation inference.
The original three controller attempts all remain exit 1. Their causes were an
unwarmed statement, an observer-side transaction lifecycle error, and an overly
strict full-query comparison against a shorter observed pg_stat query respectively.
The final nine-case recorder itself returned `passed:true` before that last
postcapture validator failure. No application request was replayed to repair it.

Run the portable checks with Python 3:

```sh
python3 verify.py
python3 -m unittest discover -s . -p test_public.py -v
python3 -m unittest discover -s . -p test_reconstruct.py -v
python3 reconstruct.py --repo /path/to/Dispatcharr --output /fresh/source
```

The projected validators retain full warm and held SQL, actual backend and
connection identities, fresh Execute generations, 57014 errors, owner/worker/memory
states, shutdown refusal, peer transcripts and terminal pool/drain receipts.
For the long information queries, the observed pg_stat digest agrees with the
first 1,023 UTF-8 bytes; full warm-to-held wire SQL must still match independently.
The actual `track_activity_query_size` setting was not captured.

SQL parameter bytes are replaced consistently by SHA256 of their original hex
text. These are digest equality tokens, not literal raw-wire parameters. The
private comparison verifies that deterministic transformation against the bound
raw inputs. Database names are also hashed. Unused backend frame bodies, statement
names, ports and failed-case details are omitted. Public verification recomputes
the selected projected predicates; it does not recover hidden credential values,
decode hidden SQL rows, or independently repeat the original host cleanup queries.
The exact cleanup output hashes and independent reviews retain those boundaries.

The historical physical executable has its own 843 Rust plus five coupled input
binding. The separate current union has 845 Rust plus five coupled inputs and
passed workspace format, check, strict Clippy and defaults (716 passed, 735 ignored
fixture tests, 172 result blocks). Its new composition does not inherit historical
physical execution. `reconstruct.py` uses the exact immutable Git base and seven
hash-bound selected source files; it contains no private fallback or executable.

Main/application acceptance, Source error-body parity, ordinary REST auth/network
ownership, full M7 and performance remain open. Existing image57 performance has
its own immutable application binding. Original Dispatcharr authors retain credit;
the Original license is included.
