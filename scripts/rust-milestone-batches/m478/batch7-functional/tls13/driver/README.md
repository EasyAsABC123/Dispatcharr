Prepared only. Root owns the one ordinary fixture slot, SDK/image build and
physical proof. Original Dispatcharr, SQLx/rustls, Django/psycopg and PostgreSQL
authors retain all application/algorithm credit. This driver extends the actual
candidate5 Native12 controller into one grouped13-cell acceptance batch; it does
not create13 independent PG/bootstrap fixtures.

The definition reuses the qualified Source12 observations and the genuinely new
Source allow/plaintext-preference observation. No Source API/driver/app function
runs. A pinned Original image supplies only the already retained PG17 bootstrap
shells, schema SQL and installed raw psycopg HTTP/SQL observer environment. The
new Native storage fixture does not bind Original Python source into either Main
or its storage service. All certificates are generated inside an owned Docker
volume, client/server private-key permissions match actual UIDs, and no private
key is copied to the host or publication packet.

Run without flags for a definition-only JSON description. It performs no Docker,
Cargo, application dispatch or image build. Once Root grants the slot and binds
one completed image, execute with fresh output:

```sh
python -B run.py --execute-batch \
  --image sha256:<actual-image> --git <actual-40-character-revision> \
  --proof /path/to/Root-build-review.json \
  --build-manifest /path/to/build.json \
  --source-map /path/to/exact-source-inputs.json \
  --output /home/justin/github/Dispatcharr/artifacts/rust/<fresh-output>
```

The proof/build/image/Git binding and exact packaged Rust map must agree. The
Native expectations are fixed to `verify-ca-allow-v1`: verify-ca hostname/IPv6
and allow on the TLS-required server must now succeed, and plaintext-capable
allow must retain plaintext preference. Earlier candidate5 failures remain
unchanged; the new runner never accepts the old or new behavior adaptively.

There are12 PostgreSQL Source compatibility cells and1 SQLite guard cell. A
successful full run can report12/12 PostgreSQL cells and13/13 expected Native
behavior checks. SQLite is still a required implementation gap: its expected
unsupported rejection, unchanged SQLite file, no PG fallback and Main exit1 do
not count as SQLite parity or full migration completion. Prefer's successful TLS
branch is included, while Prefer CA/fallback and Allow IO/EOF/multi-address
branches remain unmeasured.

One PG17 fixture is bootstrapped once. Twelve cells use the TLS-required server;
then one bounded HBA reload allows plaintext while retaining SSL support for the
last allow-preference cell. Actual `pg_hba_file_rules`/SSL configuration is saved
at each phase. Each actual production Main image/UID/entrypoint is recorded, and
real health status/body bytes plus target-only `pg_stat_activity`/`pg_stat_ssl`
rows establish its actual TLS, address and client-certificate state. The raw
observer retains health responses before parsing and distinguishes attempted
HTTP calls from captured replies.

A failed cell is recorded before shutdown and independent cells continue while
its actual Main/container settles. Unsettled Main shutdown blocks subsequent
reuse rather than running another app against a busy listener. Normal Main wait
exits, exact removal, full62-table/59-sequence default fingerprints, RedisDB7,

process generations are independently recorded. The batch has one900-second
