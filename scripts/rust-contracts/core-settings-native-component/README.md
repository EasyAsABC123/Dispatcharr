# Historical Native CoreSettings component

The inert Core7 component completed 32 real TCP requests using persisted fixture
API keys. All 32 captured status, content-type, response-byte, owned setting and
SQL/sequence comparisons qualified. The raw recorder deliberately retains
`passed:false`; the original controller exited 1 during its subsequent physical
case. This packet does not convert that run into a complete fixture pass.

The original timeout left default-after and backend-after audits unmeasured.
Its command inventory retains one exit-137 collector with
`physically_settled:false`, even though later independent owned-resource checks
can establish process/project absence. Physical attempt 2 is separate: case 1
passed, case 2 returned the existing Native database-error HTTP 503 where the old
controller wrongly expected 500, and cases 3–7 were unexecuted. Neither outcome
is a new Source error-status oracle or a Core runtime defect.

`verify.py` recomputes all 32 literal response comparisons, setting deltas,
unchanged other tables, sequence effects, request clocks, socket/timer closure
and mandatory 69-snapshot selected-trace integrity. `test_public.py` corrupts
coverage, statuses, bodies, schema, clocks and historical negative flags.
Original binary Redis/cache payloads, authentication values, user SQL rows and
receiver transport identities are opaque evidence objects. Therefore this is
not public recomputation of every original binary-cache predicate. That part
requires the unchanged private comparator and an independently bound review.
Harmless setting JSON, SQL fingerprints and sequences remain literal.

The credential inventory scans actual credential values in plaintext, hex and
Base64. The standalone Django unusable-password marker is not a credential;
its field is still omitted. No private-data fallback exists in public tools.
Projection-manifest entries bind each omission to original canonical JSON bytes.
The compressed projection is bounded before decompression and checked against
its declared byte count and digest.

```sh
python3 scripts/rust-contracts/core-settings-native-component/verify.py
python3 -m unittest discover \
  -s scripts/rust-contracts/core-settings-native-component -p 'test_*.py' -v
python3 scripts/rust-contracts/core-settings-native-component/reconstruct.py \
  --repo . --output /tmp/core7-exact-source
```

Reconstruction requires immutable Git base
`3b97e4f5f6fe2b3d744b93ac8aa29979b5f926b6`. It verifies all 842 base inputs,
applies exactly 11 hash-bound overlays and verifies the complete 846-input
historical dictionary (841 Rust plus 5 coupled inputs). It never reads a mutable
working tree or private artifact as a fallback. The executable is not shipped;
its source, build and executable hashes identify the historical qualification.
This historical snapshot must not replace the current Store module wholesale:
current callback and backup test registrations require narrow hunk integration.

Original Dispatcharr code and observations are credited in `Original-LICENSE`.
The nine imported persistent group-version keys are existing fixture state,
not proof of new Native network/system save signals. This component does not
activate Main or default workers. Full M5, special settings groups, ordinary
REST full-User allocation bounds, raw cache serialization, forms, broader auth,
application packaging and performance acceptance remain separate gates.

Seven finite physical cases are now separately qualified from retained continuations:
success Ready, cancelled-query ErrorResponse/Ready, logical deadline while SQL is
held, explicit caller socket loss, held Redis reply, strict ACL-induced rollback,
and four held response frames rejecting a fifth request before auth. Run
`python3 verify_physical.py` and `python3 -m unittest test_physical -v`.
The six earlier controller attempts remain exit 1; the final cases 6–7 attempt is
exit 0. The original semantic epoch has no default-after/backend-after observation.
Later default equality and cleanup do not fill that missing measurement.
