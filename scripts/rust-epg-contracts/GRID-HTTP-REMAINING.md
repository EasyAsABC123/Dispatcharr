## Earlier negotiation and method checklist

The optional `control_reads.py --grid-negotiation-source` capture is prepared, not executed. It keeps the baseline40 cases and22 successful complete entities unchanged and writes exploratory cases separately. Four caller roles (admin, standard, basic, anonymous) exercise Accept case/parameters/q=0/wildcards, JSON/API/invalid/empty/duplicate format selectors, OPTIONS, and unsafe methods. Failed cases must be retained; no native changes should be declared equivalent before this corpus runs.

Static original-code facts requiring this capture:

- `EPGGridAPIView.get_permissions()` delegates to `permissions_for_method`: GET and HEAD require Standard; POST/PUT/PATCH/DELETE require Admin; unlisted OPTIONS defaults to Admin. The initial prototype checked Standard for every method. A post-native1 static-source fix now applies these exact minimum levels; it is uncompiled/unaccepted until the exploratory Source corpus runs after quiet. The frozen40-case proof is not relabeled by that later change.
- Original DRF has JSONRenderer then BrowsableAPIRenderer. A successful grid returns StreamingHttpResponse application/json, while a rejected request uses DRF rendering. Content negotiation runs before authentication. Request Accept/format can therefore change an anonymous error before authentication executes.
- HTML errors may contain CSRF/template/session-dependent content. Record complete bodies, selected headers, and nondeterministic tokens explicitly; do not normalize arbitrary HTML and claim exact bytes. JSON errors remain eligible for literal byte comparison.
- The prototype whitelist is not a complete DRF media-type parser. Empty format values, parameters, duplicate selectors, casing, and q values need actual evidence. OPTIONS remains explicit501 rather than invented schema metadata.

## Actual original-network GET without a clock patch

Use the original server process and unmodified application code. A Python fixture creator may create only disposable rows, but must not call the original view or replace its clock when recording network evidence.

1. Record actual UTC creation time, hour anchor, and remaining seconds in the hour. Refuse setup when fewer than ten minutes remain, so a five-minute replay cannot cross the hour. Expired or hour-crossing runs fail the fixture; they are not accepted after body normalization.
2. Create owned programme rows well away from moving now/default-window boundaries. Keep overlaps, deliberately reversed heap/PK ordering, effective overrides, shared EPG assignments, adult/profile/level visibility, unmapped and standard-dummy channels. Do not shift unrelated rows or rely on stored timestamps equal to now.
3. Use explicit windows beginning at a future whole hour and ending several hours later. Original `_dummy_generation_span` then derives the dummy base and day count from the fixed window, independent of request-time now. Exact timestamps and IDs must match without normalization.
4. Also capture default/relative windows on the same UTC-hour anchor. Original standard dummy blocks use the current whole hour; stored rows are kept away from selection edges. Record before/after wall clocks around each original and native request. Verify the replay stays under five minutes and every clock remains in the anchor hour.
5. Exercise the original-network role/profile matrix, invalid window inputs, duplicate arguments, JSON errors, HEAD, and supported negotiation cases after their separate grammar gate. Compare exact status, body bytes/hash, MIME, representation Content-Length, Allow, WWW-Authenticate, Vary, and relevant existing app security headers. Date/server/request-specific timing headers are recorded, not asserted as literal equality.
6. Record source evidence as original-network HTTP, native host component as native-network HTTP, and later image25 as packaged-network HTTP. Keep these scopes separate. Factory captures remain valuable for exact pinned-time edges but cannot replace the network proof.

The current independent router is app-unwired. First run real-clock Source/native host comparison, then coordinate parent app attachment and an immutable canonical image. Only that later image can validate application middleware, actual browser guide fetch, shutdown, and regressions.

## Custom dummy programmes

Original `apps/output/dummy_epg.py` is shared by guide grid, XMLTV export, and XC. Its custom path uses third-party `regex`, not builtin `re` and not Rust's regular-expression crate. Its compile/search calls in this generator do not provide the preview consumer's100ms timeout. Preview, ingestion filters, and dummy matching therefore need separate engine/timing gates.

Current native behavior returns explicit501 for visible dummy sources with truthy custom properties before publishing an entity. This includes properties with no title pattern that original may turn into fallback or standard programmes. It is intentionally broader than only syntactically valid regex; it is not full dummy parity.

A future source corpus must cover absent/empty/nonmapping properties; missing, invalid, unmatched, and valid title patterns; JS/Python named groups and normalized aliases; date/time parsing, UTC and pytz DST folds/gaps, unknown timezone fallback, output timezone; event/upcoming/ended labels; durations, live/new/category/poster fields; fallback title/description; overlap edges; stream-name source and ordered stream-index fallback; channel/EPG overrides; malformed property types; exception boundaries and original generator continuation/truncation. Use actual original rows, pure function captures, and complete output protocol bodies. Regex search resource bounds must be explicit and must not silently discard programmes.

Static code also shows stream-name resolution occurs before the per-channel `generate_dummy_programs` try/except in the grid iterator. Some malformed stream-index properties may abort a streamed200 response after its prefix. Capture that separately from normal successful wire behavior; resource-cleanup improvements must not be mislabeled as identical failure internals.
