The accepted149/150/152 slice covers Coordinator, TaskLocks and shared RedisTransport. ClientStore, VOD SessionPool and Store NotificationCache keep separate cached multiplexed connections. Their recovery cannot be inferred from that slice.

`run_owners.py` freezes the full Rust tree and three private test peers. A network-disabled, read-only UID65532 Original container runs only owned Redis on loopback. One persistent Original peer reads actual Django cache values and the pinned `ClientManager.get_total_client_count` / `RedisBackedVODConnection.has_active_streams` methods. Those two method bodies are extracted unchanged from the Original AST and supplied their documented cached connection/keys/local state. Their constructors, heartbeat threads, providers, event publishers and full request lifecycles are explicitly outside the gate. Django application initialization is forbidden. Source bytes, test binaries, process IDs and server run IDs are captured.

Native peers invoke actual ClientStore channel-client reads, NotificationCache guarded cache reads with the shared Source cache codec, and SessionPool's actual active-count read. Seeded values must match before loss. Redis is stopped and restarted at the same port without persistence. Missing Source state must be observed first; an independent recovered Source client then seeds fresh state. A stale native connection cannot pass merely because both sides observed missing state. Cached peers are sampled at fixed0/0.1/1second delays, then reconstructed native peers provide healthy-server controls. A valid negative report records `execution_passed:true`, `migration_gate_passed:false`, never accepted application recovery.

Before production conversion each owner also needs its existing cancellation, retained-slot, replacement-fence and shutdown controls rerun against exact captured bytes. VOD currently has a two-second Redis response timeout; this differs from the first recovery slice and requires explicit pending-create/cleanup physical-reply testing. NotificationCache already owns detached commands and retains composed caller scopes through actual responses, with sixteen physical slots and256 bounded waiters. ClientStore has independent admission, heartbeat and pending-cleanup owners. Any new manager must preserve no-replay semantics and avoid releasing those owners on only a logical timeout.

This is component planning/evidence, not a packaged application, permission/TLS, process restart, deployment cutover or performance claim.
