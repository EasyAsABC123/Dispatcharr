# Bounded XMLTV bulk replies

All application credit remains with the original Dispatcharr authors and contributors. Existing AGPL licensing is preserved.

The image27 cold10 preflight failed its completion budget. It remains failed evidence; lower CPU and memory did not make it pass. Its separate resource/HTTP gates remain valid within their recorded scope.

The earlier cold functional diagnostic recorded439,545µs inside457 Redis script invocations, while2,444 LINDEX calls used4,299µs and3,650 TYPE calls used638µs. This did not prove that removing individual catalogue checks would fix latency. Code inspection identified a more direct copying cost: each native READ copied full members through Lua `string.sub` and then `table.concat`, before RESP serialization. Original `streaming_chunk_cache.py` returns LINDEX bulk data directly; its leader also yields generated data after RPUSH rather than reading it back.

This narrow change keeps every existing sweep, type/status check, TTL refresh, catalogue/fence/generation guard, stored member and leader READ. It changes only the read reply shape: Lua returns up to32 bounded bulk parts and avoids substring when an entire member is selected. Partial legacy members still use a byte-bounded substring and preserve the cursor offset. Rust validates the part count and total byte size, allocates one exact-sized frame, and assembles the parts once. Decoded parts and the assembled frame remain covered by the existing twice-reply-byte permit. The physical Redis operation retains that permit, request admission and cursor slot on cancellation; detached output frames retain their memory through the final clone.

The frozen same-data test runs both old and new Lua reply paths in alternating order, with identical208 stored members, ten consumers, body hashes,230 READ calls and unchanged sweep/status/TTL checks per phase. Joined-Lua script totals were398,922/388,237/401,865µs; bulk-part totals were167,692/157,141/169,810µs. Median ratio was0.4204. These include a commandstats observer and are a component diagnostic, not an HTTP or application performance acceptance result.

The full frozen component gate passed47 original/native HTTP comparisons, Python-written-cache interoperability with no extra audit,9 audit checkpoints,19 actual Redis/SQL/HTTP resource tests,5 unit tests and strict all-target Clippy. Tests include legacy large members, malformed later members and deferred valid-prefix errors, stale fences, generation changes, caller aborts with delayed physical replies, held slow frames/final clones, quotas and shutdown.

The actual500-channel/50-guide fixture produced identical13,015,458-byte original/native XML. Its cold10 phase retained one native leader/nine followers,203 native members and29 original members. Native461 EVALSHA calls used189,408µs, with2,448 LINDEX calls; the previous functional run recorded457/439,545µs and2,444 LINDEX. Similar command counts and the controlled same-data result support the copying explanation, but separate functional runs are not a paired endpoint performance comparison. Poll counts remain scheduling dependent.

Evidence is bound in `verified-xmltv-bulk-reply-native-1.json` and `artifacts/rust/m7-xmltv-bulk-reply-native-1`. Owned Compose resources were removed and shutdown restored request/cache memory budgets. A new canonical image, packaged regression replay and the unchanged-budget cold10 preflight are required before any completion-budget claim. Direct leader delivery, renderer templates and removal of catalogue checks are deliberately deferred so this change can be assessed on its own.
