# Predeclared parented interoperability comparison

This five-phase experiment reuses the actual Source reference with six tasks: Original Refresh (model signal), native parented Series, both actual Original artwork children, repeat Original Refresh, repeat native parented Series. New native artwork consumption is excluded. All three owned route names are unchanged from the Source fixture. Default setup and both Index frames remain intact and unconsumed. Both new native Series executions use the same normal inert constructor/service/result writer compiled in source3; test controls only supply owned routes after exact DB/guard/exchange checks and preserve original frame bytes for CAS.

Every raw snapshot, result/backend key/value, frame, event, SQL observation, filesystem stat, original and native execution receipt remains retained. Native Series has no Source task_prerun/postrun or Django SQL observation; none will be invented. Its actual command begins/ends and actual backend date_done are separate evidence. Source Original artwork executes the two actual native-generated envelopes in publication/ETA order and returns its own actual AsyncResult results.

The input programme anchor is actual fixture UTC floored to one second, plus exactly four hours, ending one hour later. This is an input-time correspondence, not a SQL execution-clock injection. Keep both reference and native instants and bind only their declared anchor difference. No timestamp key is removed. All SQL execution timestamp fields remain raw, require actual backend lifecycle/changed-operation intervals, and preserve Source-observed changed/unchanged relations per row/field across snapshots. Snapshot observations retain their own ordering; no captured Source wall clock is reused for native SQL or date_done.

All business row fields are compared with explicit row-ID, input-time, opaque model UUID and task-ID correspondences. Existing fields must precede newly generated identity bindings; a Source value coinciding with another generated input does not permit an arbitrary rebind. Metadata field presence is exact: absent root-task parent remains absent; parented Series and artwork have exact parent fields. Full metadata result values/types, child tuple shapes, ordered child identities, statuses, traceback nulls, date_done, TTL and Original get values are checked. Routing overrides are explicit fixture controls, not production-default routing parity.

Transport-origin/reply/delivery IDs and Channels serialization salts differ by runtime/process. Keep their raw fields and validate each declared schema, canonical identity, stable/repeated relationships and actual event payload rather than stripping or treating unequal bytes as identical. Redis diagnostic snapshots remain complete; semantic cache values, task lock release, queue/result preservation and allowed task effects are independently checked. This does not establish universal Redis byte serialization parity, strict observer read bounds, concurrent model/configuration parity, or default FIFO progress.

The fixture retains existing Source deadlines (35 seconds per task/process, guest600, readiness180, cleanup90). No timing/resource/performance measurement or adaptive retry is authorized. Output is fresh parented-recordings-native-1. Any failure remains literal, with raw state written before assertions and all owned processes/pipes stopped/waited/inventoried.
