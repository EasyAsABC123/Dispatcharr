# Native design after Source11 authority (not implemented/accepted)

The existing normal `series_application`, `series_rules`, protocol/worker/transport paths remain authoritative for no-rule/busy behavior. Positive recurring currently uses its typed disabled-only default-family branch. Extend these normal inert services after Source review rather than introduce cfg(test)-only replacement executors. Keep their public preparation/start/drain APIs and existing worker authority, no Main/registry/Cargo changes now.

First bounded positive domain: one dictionary rule, explicit positive channel+EPG source, one ASCII exact title/tvg, all-mode, UTC future programmes, zero offsets, finite episode identity `(season, episode)` or exact repeat key; one enabled recurring rule on exactly one UTC future date. Read known Source SQL from the actual capture before selecting the final projection. PostgreSQL case-insensitive title semantics must use the actual SQL/collation operation, not assume Rust ASCII equality models general Django `iexact`. Unknown regex/search/description modes, arbitrary date/title/episode types, unpinned channel precedence, custom/dummy/offsets/timezones/network/artwork/media execution stay unsupported.

A single bounded `PreparedRecording`/shared scheduling engine should serve Series and recurring. Preserve exact Recording custom_properties programme/rule dictionaries and source field presence/nulls. Recurring integer0 remains distinct from boolfalse. Server-side projection/serialized-text caps and row sentinel must bound actual transferred snapshots (never precheck then unbounded fetch); admission snapshots/settings cache physical errors retain the frame before ACK. Preflight predicates must not silently turn unsupported stored fields into NULL/new-row updates. Carry immutable per-execution settings/dispatcher/sink/retained caller through every query, rollback/Ready/close and actual child/result reply.

Do NOT wrap the whole Source flow in a new transaction: Recording INSERT succeeds before post_save's Clocked/Periodic/task-id saves and artwork publications, and signal/task helpers catch errors at distinct points. A future shared Store report should preserve exact stage provenance (`RecordingInsert`, `ClockedLookup/Insert`, `PeriodicLookup/Write`, `TaskIdUpdate`) and each observed commit/partial effect. Initial Source11 only qualifies Recording INSERT P0001 caught by per-programme/per-rule handling; Clocked/Periodic/publication-failure catch boundaries still require separate owned Source cases before native error semantics. Do not widen existing M3U/notification typed-error authority. Unsupported/uncertain stages stay operational, never blanket FAILURE or SUCCESS.

Scheduling a future Recording means an enabled one-off ClockedSchedule/PeriodicTask named `dvr-recording-<id>`, source-exact arguments and Recording.task_id. It is not an immediate run_recording publication. Preserve actual Beat sentinel mutations and created-row order; reuse qualified scheduler SQL/retention primitives only when their stage/commit behavior matches these model signals. Series needs TWO typed artwork publications at the Source positions (post_save then explicit task call); recurring needs ONE. Do not deduplicate them as an optimization. Artwork `countdown=1` must become actual protocol ETA from the current native command window; the old result/source times remain intact and diagnostic, no fabricated Python frames or clock transfer.

Add scoped typed publication capability only after the actual Source options/frame shape is captured. Existing Index-only and Refresh authority must not gain arbitrary child tasks. Default worker/application must still refuse unconfigured Series/rule/recording heads before ACK. No normal import→Series-positive completion claim until the legitimate artwork and recording scheduling/dispatch lifecycle is qualified and full graph handles repeat imports without FIFO stalling.

Required same-path physical followup: SQL stage Ready holds and Source-caught partial faults; logical timeout/caller abort while actual DB command pending; event reply, BOTH publication replies, denied/lost write/oldSUCCESS and TTL; shutdown/admission held until physical settlement; foreign global lock replacement and no stale writes; repeat dedup/rule-disable preserving existing recordings; all old no-rule/Series production155/disabled-recurring/inactive/default/expiry/M3U regression paths on one exact source/ELF. No resource measurements until an explicit Root quiet cue and whole declared application footprint/workload. Source11's parent-only route is component authority, not this whole workflow gate.
