# Predeclared temporal comparison policy — before ANY native results

Retain all raw Source/native timestamps, nullable fields, timezone/precision, file stat/marker bytes and backend metadata. No field is deleted or replaced by an arbitrary constant to make a comparison pass. Source17 data and executed tools remain immutable.

For each Source parent, derive the actual command envelope from transport-ledger `parent-published-before-worker-start` epoch through `parent-postrun-before-result-assertion`. For its child phase use `default-children-before-consumer-start-and-shape-assertion` through the first `before-check:<label>-all-descendants-actually-complete` epoch. These are actual real-clock observer bounds, independent of the ledger's documented backend wildcard defect. Source and native run at different real dates; compare date fields by the declared mutation/preservation semantics and each backend's own actual command envelope, not equality of wall dates.

The future Native controller must record real UTC/epoch just before each command dispatch and after its physically settled response/drain, as well as prior state. Parent-created account/profile/Beat fields belong in the parent interval. Stream insertion/update/touch and audit/event creation belong in the child interval. Field presence and SQL NULL/JSON null distinctions remain exact. For preserved fields (e.g repeated import updated_at and foreign owner/profile/stats/local-file metadata), compare exact before/after values within each backend. For Source-observed changed fields, require the matching Native mutation class and a value in that backend's actual command interval. last_seen touch must advance/preserve consistently with the observed trace and clock resolution; reject regression. When Source establishes cross-field nondecreasing time order, require that order without inventing an exact elapsed microsecond gap. Report ties/precision honestly rather than making a distinct-time requirement beyond clock resolution.

Track timestamp origins across the whole repeated/cross-account sequence: a field preserved from a prior step remains bound to its original recorded backend interval. Do not transplant Source wall dates into Native writes. Existing restored fixture inputs intentionally copied from Source retain their exact input values and must be distinguished from new writes.

Keep all task date_done fields and validate newly written results against their own actual command interval; lineage/typed result/status/children remain exact. Existing SUCCESS metadata preservation, if tested separately, preserves original raw bytes/date rather than being incorrectly forced into a later interval. Raw integer TTL samples remain retained; use the declared3600s result policy plus actual elapsed sampling/second granularity, never an equality requirement between independently observed TTL seconds. No missing backend map is interpreted as absent results; use explicit app.backend keys.

Controlled scanner now/mtime/float marker bytes are fixture inputs and compare exactly. Module-local elapsed0.0 is explicitly injected in both fixtures and compares exactly; it is not a real-duration claim. Native-ready/SQL/owner timing remains actual elapsed observation. Unrelated worker-heartbeat exclusions, if reused from the accepted harness, must retain the exact documented structural rule and raw snapshots; no new timestamp/key normalization is introduced.

Before actual Native runs, implement negative controls for missing temporal fields, changed preserved updated_at, out-of-window new timestamps, regressions, wrong-null shape and ignored date_done. Any field whose origin/window cannot be proven stays an explicit unresolved comparison, not an omitted pass. This policy is frozen for Root review before execution and is not itself a passing test.
