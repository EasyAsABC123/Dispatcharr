Original Dispatcharr, Django, Celery, PostgreSQL, Redis, Channels and all dependency authors retain code, algorithm and license credit. This one-file revision builds on canonical e6e2f9bd47cd3c7715f5f39db93edff2fca1ad39. It keeps the normal inert library/constructor paths and does not enable Main, default consumers, HTTP202 or the complete scanner graph.

The previous component refused a full audit history. The new admitted domain follows actual Source323: INSERT first; count; when count>configured limit select `ORDER BY timestamp DESC LIMIT1 OFFSET limit`; then DELETE **id<cutoff id**. No id tie-break, OFFSET limit-1, fixed-row retention rewrite or post-diff sorting is added. A zero-row delete and max+1 retained rows are real Source outcomes. Initial history is capped at10000, with at most one owned pending insertion10001; observed over-cap snapshots remain operational; concurrency parity is unqualified. Count/tie/cutoff read from the same bounded MATERIALIZED history snapshots (LIMIT10001 before admission, LIMIT10002 after the owned insert), so later writers cannot enlarge the GROUP BY/sort input. The LIMIT bounds materialized tuples, not all physical rows/pages PostgreSQL may scan; DELETE keeps the exact Source id predicate and its execution plan/work is not strictly capped. No strict database CPU/IO bound, global writer exclusion or atomic concurrent-history guarantee is claimed. Payload/file/parser/worker budgets are unchanged.

There is no settings or tie-domain expansion. Settings remain absent/null/0 =>100 or integer1..10000. Unsupported scalar types/ranges remain before-ACK refusals. Trimming with equal existing timestamps is refused before ACK; a late tie is operational. The Source equal-timestamp case remains an observation, not stable ordering authority. General concurrency and count/cutoff read/IO/decode failures are unported.

`SettledAuditFailure` owns the statement stage and original SQLx cause and is constructed only after actual trailing ReadyForQuery/ping/close settlement. Only PostgreSQL severity ERROR/codeP0001 from the guarded audit INSERT or DELETE is caught into the observed normal result. Unknown error classes/codes remain operational. This does not extend notification failure authority, emit Python imports or manufacture tracebacks. Source emits `logger.error` for caught audit failures; Native currently returns silently, so operator-log parity is explicitly open. Native reads settings before INSERT while Source reads them afterward: the qualified contract has stable injected settings, not concurrent configuration/order parity. The whole audit helper is not claimed1:1. Typed normal result metadata still uses the unchanged common writer/oldSUCCESS/TTL path.

The prior pre-CAS guard against installed user triggers is preserved. Therefore the known fault controls explicitly hold a real admitted CAS/pop reply, install the owned trigger, and release that reply before execution. They qualify **post-admission known server failures**, not arbitrary preinstalled trigger configurations. The initial trigger refusal is retained evidence, not hidden or relabeled as parity.

The15-case actual comparison has24 native tasks: groups15 and single9; six unsupported single calls are retained before ACK and completed by real Original fallback. Native-supported cases compare ordered SQL rows/audit IDs, events, files/cache values, typed Original AsyncResult and partial P0001 effects against Source323. Date creation/update/last-seen/timestamp fields are excluded from equality as documented in the original M3U reference; TTLs have separate bounds. Elapsed clock remains explicitly0.0, not a general timing/float formatting claim. No generic task-family authority changes.

The physical cohort forwards real PostgreSQL errors and holds their trailing Ready for6.2s beyond the existing5s pool acquire timeout. INSERT/DELETE P0001 retain caller/admission/shutdown until physical release, then return the normal string with exact partial audit effects. A real P0002 negative remains operational/PENDING after settlement. No statement retry occurs. Actual10000-row admission retains10001 after the owned insertion and zero-row Source-shaped delete;10001 initial rows are refused before Single ACK with queue/model/cache retained.
