## Authority and lifetime

`Jobs` distinguishes fixture, programme-index and refresh authority. The new refresh constructor must reject backup/restore publication/consumption, while the existing index-only constructor must continue rejecting refresh. Publishing a typed parent or captured child retains caller, task admission and command bytes through the actual Redis reply. Physical completion, not a timed-out waiter, releases ownership.

The immediate poller preserves unknown/ETA/parented FIFO heads and exposes `UnsupportedHead`. Its stop request closes intake, waits the actual worker, and then waits the polling loop using one absolute deadline. It never closes a shared transport. The application owner must drain accepted HTTP publication, the consumer, runner/importers/reporter and finally the shared jobs transport in that order.

## Explicit unresolved scope

The Source view forwards null, nonpositive, boolean, numeric-string and float IDs unchanged. The proven typed native protocol currently supports positive integer source IDs. The application service therefore rejects other shapes explicitly; it does not claim the Source37 corpus completely matches. Form/multipart parsing, empty-body details and browsable HTML also need actual gates beyond the JSON browser path.

Successful local imports may queue programme-index and SeriesRules children. The immediate-refresh poller must leave those heads intact until their supported family consumers are composed. ETA refresh consumption, remote/provider tasks, concurrent newly mapped late-programme fanout, scheduler startup and generic task failure/result projection remain separate. A retained unsupported head can block the shared FIFO; exposing that state is required, and no whole-M6/default-queue acceptance follows from a single successful import.
