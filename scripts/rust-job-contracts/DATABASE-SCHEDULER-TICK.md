# Known-interval database scheduler component

Original Dispatcharr authors retain application and algorithm credit and AGPL licensing. Celery and django-celery-beat authors retain their framework credit and licenses. The implementation follows the pinned Original; it does not claim independent invention of its scheduling semantics.

`verified-source-native-scheduler-tick-2.json` binds the final immutable source to 47 setup/resource checks, three actual physical-resource tests, and 108 full tick checks (49 Original checks plus 59 native comparisons). Both disposable copied-database projects were removed and their default databases remained unchanged. No production scheduler registration or default intake was enabled.

The native component installs the six observed defaults, reloads through the database change sentinel, and accepts zero or one enabled known interval entry. It publishes only the observed refresh or no-rules Series task with default routing/options. It reserves the cached run state before publication and syncs that cached state to SQL. An actual LPUSH-denied producer preserves the observed Original reservation behavior. Initial completed one-off and expired entries reproduce the observed 4.99-second decision; ordinary due, future-start and later decisions match the captured values. A bulk-disabled row without a sentinel remains stale in the cache, matching the reference. Four directly published native messages were consumed by real Original workers; their real AsyncResult values matched, without requeueing or replacing task handlers.

`periodic_task_name` is the only additional accepted periodic header. Its bounded normalization preserves strict validation of all other fields and existing constructor authority. The earlier 46-check periodic publisher proof independently covers wrong-family rejection and actual Original worker request/result metadata; the final tick replay exercises the same publication path.

The server-side loader limits the candidate count to 256 and string aggregate to 1 MiB, with bounded individual fields. Oversized field, aggregate and count cases return metadata-only SQL sentinels rather than oversized payloads. Final measured server replies were 1086, 304 and 249 bytes, respectively. These are SQL reply bounds, not a total process RSS claim.

The physical tests hold real PostgreSQL replies and Redis publication replies. Aborted callers and logical deadlines retain the scheduler admission, caller scope and actual command ownership. Capacity rejects a third admitted operation. A short shutdown reports incomplete; after actual replies arrive, shutdown drains publication and performs retained final SQL sync. The test observed two durable publications and persisted count two, with both caller scopes released only after actual completion.

Historical failures remain available: database-scheduler runs 2 and 3 passed their runtime observations but failed the proxy teardown assertion; run 4 corrected only explicit test-proxy shutdown after observed completion. Tick inputs 1–3 preserve compiler failures. Tick run 1 retains its earlier admission implementation; run 2 and retained run 5 share the final exact runtime hash map. Earlier evidence has not been relabeled.

Still open: automatic timer/application startup, multiple enabled entries and heap/tie ordering, multiple dirty entries, arbitrary routing/options and task families, calendar/timezone/DST decisions, process crash windows and restart recovery. Configured Series recording rules remain separately unsupported. Existing unknown FIFO task handling and disabled-by-default worker configuration are unchanged. A passing known-interval fixture does not close M6.
