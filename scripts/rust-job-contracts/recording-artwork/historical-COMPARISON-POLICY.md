# Predeclared parented interoperability comparison

This five-phase gate reuses the actual Source reference with six tasks: Original Refresh (model signal), Original parented Series, two native local-VODLogo artwork children in serial actual processes, repeat Original Refresh, repeat Original parented Series. All three owned route names remain identical to the Source fixture. Setup and both default Index frames remain intact and unconsumed. The two native artwork executions use normal inert Store/service/worker/result writer compiled in artwork source6; test controls supply only the exact owned artwork route after copiedDB/disposable guard/exchange checks and preserve original bytes for CAS. Completed Refresh→Series authority, actual completed Series metadata and actual Original artwork frame bind the child capability.

Every raw snapshot, result/backend key/value, frame, event, SQL observation, filesystem stat, original and native execution receipt remains retained. Native artwork has no Source task_prerun/postrun or Django SQL observation; none will be invented. Its actual command windows, typed confirmed SQL changed/no-write outcome and actual backend metadata are separately retained. Original workers produce both real artwork envelopes; native workers consume them in actual FIFO/ETA order. Original AsyncResult reads both native terminal values/types. Source first UPDATE1/event1 and second UPDATE0/event0 are compared to actual native Service.changed true/false plus complete SQL row snapshots and per-task event deltas. This does not claim Native SQL query-count or wire capture.

The input programme anchor is actual fixture UTC floored to one second, plus exactly four hours, ending one hour later. This is an input-time correspondence, not a SQL execution-clock injection. Keep both reference and native instants and bind only their declared anchor difference. No timestamp key is removed. All SQL execution timestamp fields remain raw, require actual backend lifecycle/changed-operation intervals, and preserve Source-observed changed/unchanged relations per row/field across snapshots. Snapshot observations retain their own ordering; no captured Source wall clock is reused for native SQL or date_done.

All business row fields are compared with explicit row-ID, input-time, opaque model UUID and task-ID correspondences. Existing fields must precede newly generated identity bindings; a Source value coinciding with another generated input does not permit an arbitrary rebind. Metadata field presence is exact: absent root-task parent remains absent; parented Series and artwork have exact parent fields. Full metadata result values/types, child tuple shapes, ordered child identities, statuses, traceback nulls, date_done, TTL and Original get values are checked. Routing overrides are explicit fixture controls, not production-default routing parity.

Transport-origin/reply/delivery IDs and Channels serialization salts differ by runtime/process. Keep their raw fields and validate each declared schema, canonical identity, stable/repeated relationships and actual event payload rather than stripping or treating unequal bytes as identical. Redis diagnostic snapshots remain complete; semantic cache values, task lock release, queue/result preservation and allowed task effects are independently checked. This does not establish universal Redis byte serialization parity, strict observer read bounds, concurrent model/configuration parity, or default FIFO progress.

The fixture retains existing Source deadlines (35 seconds per Source worker; the two serial Native artwork processes share a total35-second phase deadline; guest600, readiness180, cleanup90). A single predeclared wait until each actual wire ETA is bounded at2seconds inside that same phase deadline; no NotDue retry. No timing/resource/performance measurement or adaptive retry is authorized. Output is fresh local-artwork-recordings-native-1. Any failure remains literal, with raw state written before assertions and all owned processes/pipes stopped/waited/inventoried.
