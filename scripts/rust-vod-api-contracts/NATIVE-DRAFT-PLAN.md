# VOD REST native draft and next gates

All application and algorithm credit remains with the original Dispatcharr authors and contributors. Existing AGPL licensing is preserved.

The original Source1 corpus passed465 Factory and463 real HTTP cases. The code-only files `vod_api_projection.rs`, `vod_api_dto.rs`, `vod_api_pagination.rs`, and `vod_api_source_tests.rs` are unregistered, uncompiled, unrouted drafts. They were written during the image28 performance quiet window. No native policy/projection test has run, and no Source forced-refresh or artwork behavior is claimed.

The draft preserves the recorded field insertion order, nullable strings/JSON, nested series and full versus slim logo shapes. It distinguishes standard string ratings from unified floating ratings and preserves the unified branch's falsy-string/JSON conversions. UTC timestamps keep six fractional digits when nonzero. The HTTP caller must supply the shared trusted-origin rules; providers/series-episodes intentionally have no request context for relative nested artwork URLs. Logo usage/name queries count all content, including invisible/inactive rows; Source's advertised ten-name limit is actually ten movies plus ten series.

LiteralFalse access flags differ from truthiness: numeric0 keeps content enabled. Movie adult filtering applies only to ordinary movie views and nonadmins; unified rawSQL omits it. Top-level episodes require an active episode provider but not an active parent-series provider. The series episodes action returns providerless episodes as well and filters only their nested providers. Category display DTOs retain every account relation rather than only active/enabled ones.

Ordinary pagination defaults20, caps100, falls back to20 for malformed/nonpositive size, recognizes exact `last`, and gives404 Invalid page for invalid/out-of-range pages. QueryDict chooses the last duplicate. Unified pagination defaults24 and uses Python int plus raw PostgreSQL LIMIT/OFFSET with no100-row cap: page_size0 is a successful empty result with a possible next link, while malformed/negative parameters produce captured500 errors. The draft retains BigInt until SQL binding and deliberately leaves exact fault text/URL encoding for an explicit next gate.

## SQL and ownership design

Use request/admission/response-byte ownership before authentication or any database/cache work. Keep a supervised worker through actual query cancellation/rollback after caller abort or logical deadline. Response frames retain independent memory through their final clone, without retaining admission indefinitely. Count/metadata/row limits must fail explicitly; they must never silently omit content, relations or nested metadata.

Ordinary base visibility uses independent EXISTS clauses for active relations, then independent EXISTS for each relational filter. Source's initial active-account join can match a different relation from a later account/category filter: combining all predicates into one active relation would change results. A category name and its final recognized type share one category relation, while separate account/category filters can use different relations. Detail routes apply the same filters/search as lists before selecting the requested ID. Preserve default database ordering and ties; do not invent an ID tie-break for Source lists that do not have one. Unified uses its explicit LOWER(name),id and UNION ALL.

Select only the requested ordinary page and bulk-load nested metadata for those IDs. Bound raw JSON/text bytes before decoding large payloads, then retain reservations through typed rows, serialization and detached frames. Fetch logo counts and the first ten movie/series names in bounded lateral/batch queries without changing their model default ordering. Nested Series episode_count includes all its episodes; it is not a count of the current visible/provider-filtered page. Avoid one query per nested DTO while preserving Source context and multiplicity.

Preserve search distinctions. Ordinary DRF search uses its smart-split token grammar and conjunctive terms over the declared fields, with Django PostgreSQL case-insensitive escaping. Unified searches only name with raw LIKE wildcard semantics, and Python-pinned lowercase before SQL. Rust Unicode lowercase, one SQL wildcard rule, or a generic full-text index is not automatically equivalent. Ordering must use captured field allowlists, never interpolate arbitrary query text into SQL.

Category GET permission/auth happens before lazy mutations; mutations occur before its access flags/filter/pagination. Ensure both global Uncategorized types, then missing links for active XC accounts with truthy enable_vod, preserving existing link.enabled/properties. Missing defaults are true/empty object. SQL uniqueness resolves concurrent get_or_create races, but do not overwrite with ON CONFLICT UPDATE. Source commits individual get_or_create operations; one all-or-nothing native transaction would change partial-error behavior. Characterize malformed defaults and injected failures before selecting a transaction policy or claiming fault parity. The draft retains raw auto-enable values instead of coercing all truthy values to BooleanField values.

Unified data and count are separate original queries; concurrent updates can produce their own observations. Document transaction isolation/row coherence explicitly and test concurrent changes rather than inventing a stronger snapshot and calling it literal parity. Preserve lazy-write and provider-info side effects separately from a read-only DTO cache.

## Execution after quiet release only

First register the pure files in an isolated component peer/tests, not app routes. Run the Source-derived projection tests and expand them across captured field/null/context cases. These response-derived-row tests check serializer shape only; they do not establish SQL correctness. Compare native actual PostgreSQL queries against a newly captured original fixture with the same seed rows, fresh provider flags and loopback trap. Reuse fixed Source1 methods/roles/query grammar, compare complete bodies/status/header order and all category row effects, and justify clock/ID normalization narrowly. Recheck actual wire HEAD separately from Factory rendering.

Add explicit Unicode/search/quotes/duplicate-order/numeric boundary cases, null/zero/negative rating and timestamp precision, many-logo/shared-series query-count evidence, relational filters whose active and matching relations differ, inactive parent/providerless episodes, and concurrent lazy category creation/default preservation. Retain the two artificially blocked forced-refresh observations as exclusions; build a separate owned provider refresh fixture before implementing stale/forced provider-info. Artwork reads/writes and generic VODLogo mutations remain separate gates.

Physical tests must lock real PG relations, abort callers and exceed logical deadlines while proving admissions persist through rollback; hold/final-clone output frames; test byte/counter limits near boundaries and large unified/unpaginated actions without silent truncation; inject SQL failures before/after lazy category writes; and prove worker/task/process cleanup on shutdown. Only after these pass should parent authorize app/library registration and a new canonical image. Then unchanged React browser page flows, generated playback URLs, exact packaged Source1 replay and isolated CPU/memory/latency measurements are still required.
